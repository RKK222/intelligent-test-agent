# 2026-09-18

## 本地工作空间开放聊天附件（release 分支）

- 用户诉求：本地工作空间对话时「上传附件」按钮不可用，要求开放限制并可正常使用。
- 结论：不是 bug，是两处有意关闭 —— ① 本地工作区/实例 capability `attachments=false`；② `RunApplicationService.startRun`
  用 `LocalRuntimeCapabilityGuard` 对本地工作区的 `workspace_attachment` part 无条件 fail-closed。
- 关键判断：关闭的唯一实际理由是"服务端无法把客户端路径变成 `file://`、也不能把正文内联进 1 MiB 的本地隧道
  （`LocalClientOpencodeWebClientTransport.MAX_REQUEST_BODY_BYTES`）"，但"投递工作区相对路径、由客户端 OpenCode 自己读"
  完全不受影响，所以走降级路线而不是继续关闭。
- 改造点：3 处 capability 改 `true`（`WorkspaceApplicationService.localCapabilities()`、`LocalWorkspaceApplicationService`、
  `LocalClientInstanceApplicationService`）；删除 Run 入口守卫与其无用字段/setter/import；`toAgentPromptParts` 链路
  增加 `RuntimeKind` 参数，新增 `usesWorkspacePathDelivery()` 让 `LOCAL_CLIENT` 无条件走相对路径 text part；
  前端只改文案（capability 数据驱动，无逻辑改动）。
- 上传协议无需新增：`LocalClientFileRpcHandler` 早已支持 `workspace.upload.begin/chunk/complete`，
  `LOCAL_WORKSPACE_OPERATIONS` 也已包含。
- 验证：`mvn -pl test-agent-opencode-runtime,test-agent-workspace-management,test-agent-system-management -am test`
  BUILD SUCCESS（0 失败），新增单测 `localRuntimeDowngradesNativeWorkspaceAttachmentToWorkspacePath` 通过。
- 未验证：Windows 真机（`E:\` 盘符）客户端读取附件，已列入 `docs/deployment/local-opencode-client.md` 现场验收清单。
