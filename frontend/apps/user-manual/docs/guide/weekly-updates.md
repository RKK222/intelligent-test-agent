### 精确引用资产库中的二级 spec 目录

**适用场景：** 资产库把规格资料放在 `ai-agent/spec` 一类的嵌套目录中，只需接入该 `spec`，不让 Agent 或文件树看到父目录的其它资料。

**使用前配置：** 仅应用管理员或超级管理员可保存引用。超级管理员在“系统管理 → 通用参数”把 `REFERENCES_SDD_FOLDER_NAMES` 配置为小写的精确路径（例如 `docs,spec,ai-agent/spec`）；应用已关联资产库且当前服务器副本就绪。

**怎么用：**

1. 在工作台选中应用和个人工作区，打开工作空间切换按钮后的“引用配置 → 应用资产库”。
2. 在已就绪仓库的树中展开 `ai-agent`，点击蓝色的 `spec`；父目录只供展开。
3. 填写描述后保存。`ai-agent/spec` 会完整记录源路径，只合并到工作区 `spec/`，不挂载或授权 `ai-agent/`；内容仍只读，且不进入个人 Git、搜索、Git Diff 或 `requirements`。

完整同步、权限和冲突处理见[引用配置](./reference-config.md)。

### 已有测试工作空间，直接新增一个版本

**适用场景：** 已经选好应用和测试工作空间，但版本列表为空，或者需要为同一个工作空间新增一个日期版本，不必回到设置页重新创建工作空间。

**使用前配置：** 当前账号需要能进入目标应用，且关联 Git 的读取权限可用；当前 TestAgent 进程也需要已准备好。标准测试工作空间需要远端已有 `feature_testagent_yyyyMMdd` 分支；兼容的非标准工作空间还需要日期版本。源码快照、本地工作区和 Git 权限失效的工作空间不能从这里新增版本。

![工作台顶部连续显示应用、工作空间和版本入口；先在这里选中目标测试工作空间](./images/operations/automation-workspace-switch.png)

**怎么用：**

1. 在顶部依次选择应用和目标“测试工作空间”。
2. 打开顶部“版本”菜单，点击已有版本列表下方带「＋」的“按分支新建版本”；也可打开左下角工作空间菜单并悬停目标工作空间后创建。
3. 标准测试工作空间直接选择已有远端分支，版本号从分支名自动识别；兼容的非标准工作空间仍需补充日期版本。分支未选时“确定”不可点击。
4. 点击“确定”后等待平台创建版本、准备当前账号的 `default` 个人工作区并自动切换。看到“已切换应用版本”或“新增版本成功”即可继续编辑和对话。

新增版本不会复制当前个人工作区里尚未提交或尚未发布的修改。标准分支尚不存在时，请先在开发者门户创建分支；若页面提示 Git 权限失效，先恢复版本库访问权限再重试。完整边界见[应用版本与个人工作区](./workspace.md#基于已有工作空间新增版本)。

### 麒麟 ARM64 客户端改为普通用户安装

**适用场景：** 需要在自己使用的麒麟 ARM64 电脑上运行本地 OpenCode，并把本机项目目录注册为工作区。

**使用前配置：** 客户端仍按账号灰度开放。超级管理员在“系统管理 → 用户管理”为账号打开“客户端灰度”后，网页才显示 Client Key、本地工作区和下载入口；打开灰度不会自动安装、启动或连接客户端。

![个人设置中的本地 OpenCode 客户端区域：Client key 只显示掩码，已连接的麒麟 ARM64 客户端会显示在线状态](./images/operations/settings-local-client-key.png)

**怎么用：**

1. 在“设置 → 个人设置 → 本地 OpenCode 客户端”的 **Client key** 卡片点击“创建”。密钥只在创建或轮换后显示一次，立刻复制保存；之后页面只显示掩码。
2. 在同一“本地 OpenCode 客户端”区域点击“下载最新客户端包”。当前只支持麒麟 ARM64。
3. 完整解压下载的 `tar.gz`，再双击解压目录中的 `TestAgent-Local-Client`。不要在压缩包预览窗口内直接运行，也不需要 sudo；按向导输入统一认证号和 Client Key。
4. 看到客户端在线后，点击系统托盘中的 TestAgent 图标，选择“选择并注册工作区…”，在系统目录窗口选中项目目录并确认。客户端用目录名作为默认工作区名称，注册不会上传、复制或删除该目录。
5. 注册成功会自动打开对应工作区；若浏览器没有自动打开，再点击托盘“打开网页”，然后在工作台顶部“工作空间 → 本地工作区”选择刚注册的目录。

若桌面环境没有系统托盘，或需要手工登记目录，可在“个人设置 → 本地 OpenCode 客户端”的“网页兜底注册本地工作区”中选择在线客户端，点击“网页浏览”后选择目录再注册。旧客户端如果显示“不支持自更新”，请重新下载用户包；不要再寻找 DEB 安装包。关闭客户端灰度只隐藏网页入口和本地工作区投影，不会停止客户端、重启本地 OpenCode 或撤销 Client Key。完整说明见[设置与权限内操作](./settings.md#普通用户个人设置)。

### 客户端重连后恢复历史本地工作区

**适用场景：** 客户端重启、覆盖升级、重新安装，或旧客户端被新的在线实例替换后，希望继续使用曾经注册过的本地目录。

**使用前配置：** 账号仍需开启“客户端灰度”，并且本机客户端已用当前有效 Client Key 成功连接。该自动恢复只核验当前账号的历史登记，不会上传或扫描未登记目录。

客户端上线后，平台会逐项核验历史目录的真实路径和文件系统身份，匹配的目录会恢复到当前在线客户端。等待“个人设置 → 本地 OpenCode 客户端”显示在线后，从顶部“工作空间 → 本地工作区”选择已恢复的目录；不要重复创建同名工作区。目录已移动、已删除或身份变化时会被跳过，改用托盘“选择并注册工作区…”选择实际位置。

### 在左侧活动栏添加常用内网页面

**适用场景：** 经常在工作台和质量看板、文档站或平台同源页面之间切换，希望把入口固定在自己当前浏览器的左侧活动栏。

**怎么用：** 点击能力库之后的 `+`“添加自定义菜单”，填写菜单名、选择图标、输入地址后点击“添加菜单”。最多保存 10 项；地址只能使用无账号密码的 HTTP(S) URL，或以 `/` 开头的平台同源路径。点击菜单会在中央 Tab 打开，页面顶部可刷新或“在新窗口打开”。

自定义菜单是当前账号在当前浏览器的本地偏好，不会同步给其他用户、浏览器或设备，也不会写入应用、工作区或 Git。外部站点拒绝嵌入时，使用“在新窗口打开”。完整限制和编辑/删除方式见[设置与权限内操作](./settings.md#自定义左侧菜单)。

### 从 Agent 或 Skill 配置树快捷提交

**适用场景：** 已经完成单个 Agent 配置文件，或一个完整 Skill 目录的修改，需要直接进入提交发布流程。

应用管理员或超级管理员在有写权限的公共或应用 Agents 配置树中，点击普通文件行尾的“提交并推送”；Skill 只在 `skills/<技能名>` 一级目录显示该按钮。平台自动暂存目标文件，或该 Skill 目录中的全部变更，然后打开提交信息框并复用原有推送流程。

该入口不会夹带同一作用域的其他修改：存在冲突、待重新推送的提交或其他已暂存文件时会拒绝继续，先到“变更”处理。取消提交信息框不会撤销已暂存内容；页面明确显示推送成功前，内容尚未发布。完整规则见[Agent 与 Skill 配置](./agent-config.md#快捷提交单个-agent-文件或-skill)。

### 取消已跟踪 Agent 或 Skill 的删除

**适用场景：** 删除已经提交过的普通 Agent 文件或一级 Skill 后，在填写快捷提交信息前发现删错了内容，希望恢复到删除前的 Git 状态。

**使用前配置：** 当前账号必须对目标公共或应用配置有写权限；文件或 Skill 必须已有 Git 跟踪记录。刚创建且从未提交过的临时文件删除后没有 Git Diff，因此不会打开快捷提交弹框，也无需执行恢复。

![Agents 配置树中可从文件或一级 Skill 行尾进入删除和提交操作](./images/operations/agent-config-tree.png)

**怎么用：**

1. 在左侧“Agents”配置树中删除一个已提交过的普通 Agent 文件或一级 Skill，并在“删除文件”确认框选择“确认删除”。
2. 平台确认 Git 删除记录并自动暂存后，会在当前工作区上方打开“提交并推送 Agent 文档”或对应 Skill 的提交信息框。
3. 若决定不删除，点击“取消删除”。平台会恢复文件、清除该文件的 Diff，并刷新配置树和已经打开的标签。
4. 若继续删除，填写提交信息并完成既有“提交并推送”流程；普通“取消”只关闭弹框，仍保留自动暂存的删除记录。

多文件批量删除仍在“变更”中统一处理；Git 冲突、待重新推送提交或同一作用域已有其他暂存文件时，先处理这些状态。完整规则见[Agent 与 Skill 配置](./agent-config.md#快捷提交单个-agent-文件或-skill)。当前没有“提交并推送 Agent 文档 → 取消删除”弹框的脱敏真实截图；需要人工补拍该弹框与“取消删除”按钮的同屏状态。

### 在文件树中连续选择相邻条目

**适用场景：** 需要对一段相邻的工作区文件和目录统一删除或剪切，不必逐项按住 `Ctrl/Cmd` 点击。

**怎么用：** 在可写工作区文件树中，先普通点击一个文件或目录建立锚点，再按住 `Shift` 点击另一项。平台按当前页面从上到下的可见顺序选择两点之间的条目；展开目录的后代参与，折叠目录的后代不参与，只读引用和混合目录会自动跳过。右键后可统一删除或剪切；只有选中项全部是文件时才提供复制。`Ctrl/Cmd` 多选仍可与连续选择配合使用。

这项能力只适用于可写工作区，不会放开引用内容的编辑、移动或删除权限。当前没有可复用的脱敏真实连续选择截图；需要人工补拍“工作台 → 工作区文件树”中锚点、Shift 选区和右键批量菜单的同屏状态。

### 版本库检索、Markdown 图片与应用运行态

- **版本库检索：** `APP_ADMIN` 或 `SUPER_ADMIN` 在“设置 → 版本库管理”按 ID、中文名、英文名或 Git 地址检索，清空关键字恢复全量；远端操作仍使用本人 SSH Key。进入“应用管理”会先加载顶部当前应用，展开选择器时才读取全部候选。详见[设置与权限内操作](./settings.md#版本库配置版本库管理)。
- **Markdown 图片：** 在可写工作区的“新建/上传”中同时选择 `.md` 与图片，或上传整个目录保留层级。缺图不阻断上传，已有图片继续预览，缺失项显示“图片未上传”；外链和 `data:` 图片不走工作区读取。详见[应用版本与个人工作区](./workspace.md#文件操作与-git-变更)。
- **应用运行态：** 仅 `SUPER_ADMIN` 可进入“系统管理 → 配置管理 → 应用运行态更新”，核对发布摘要、服务器和待处理用户，再按需受管重启或停止；Git 与个人 worktree 同步仍在“应用 Git 刷新”完成。失败时保留状态与 `traceId`。详见[设置与权限内操作](./settings.md#超级管理员查看应用运行态更新)。

这三项暂无与当前页面完全一致的脱敏真实截图；需要人工分别补拍版本库检索结果、Markdown 上传与缺图预览，以及应用运行态发布摘要和折叠明细。

### 不进入应用，也能先体验完整工作台

**适用场景：** 第一次接触平台、暂时没有所属应用，或者想快速试用文件编辑、终端、对话和 Git，又不想先准备正式工作空间。

**使用前配置：** 普通用户无需加入应用，也无需自己配置目录；只要登录后本人的 TestAgent 进程可用即可。首次进入时如果进程尚未启动，按页面提示初始化。平台管理员通常无需改默认值；只有需要把体验目录放到指定磁盘时，才在通用参数中配置 `OPENCODE_EXPERIENCE_WORKSPACE_DIR`，并确认目标目录可写。

4. 需要保留一组本机修改时，打开“变更”，暂存文件并建立本地提交。
5. 体验结束后再次点击同一个烧瓶按钮“退出平台体验”。有应用时会优先回到进入前的应用工作区；没有应用时回到普通空态。

:::

### 长期记忆会在新任务中自动复用经验

**适用场景：** 希望平台记住“回答先给结论”“缺陷结论要附复核证据”等可重复使用的个人偏好或团队经验，不想每次对话都重新说明。

**使用前配置：** 该能力按账号灰度开放。普通用户无需配置模型或服务参数；如果左侧没有“记忆”入口，联系平台超级管理员确认开放范围。超级管理员在“系统管理 → 记忆能力”统一配置一次 Mem0、Embedding profile、固定 CHAT 模型和抽取策略，再到“系统管理 → 用户管理”打开目标账号的“记忆灰度”。应用管理员只负责审核本应用的团队记忆候选，不能代替超级管理员开放账号。

**怎么用：**

1. 已开放账号从左侧活动栏打开“长期记忆”。未开放账号不会显示入口，直接访问记忆页面也会回到工作台；原有对话和任务仍可正常使用。
2. 在“我的记忆”中添加个人记忆，并选择只用于当前应用还是本人的所有应用；已暂停或已归档的记忆不会进入新任务。
3. 需要团队复用时，把记忆提交到“团队记忆”，等待应用管理员审核。团队候选在批准前不会影响其他成员。
4. 新任务真正引用记忆后，完成结果旁会显示“参考了 N 条记忆”；没有显示只代表本轮没有实际使用记忆。

![普通用户在长期记忆中查看个人记忆的来源证据和使用状态](./images/operations/memory-center.png)

已经稳定复用的经验还可以发起 Skill 提案，再到 Skill Hub 完成 Git 和发布流程。来源证据、审核与归档规则见[长期记忆](./memory.md)。

### 在自己的电脑上使用本地 OpenCode 和本地目录

**适用场景：** 项目目录和 OpenCode 需要运行在自己的麒麟 ARM64 电脑上，希望仍从工作台选择该本地目录、查看实例状态和维护 Client Key。

**使用前配置：** 本地客户端与长期记忆一样按账号灰度开放，但两项开关互不影响。超级管理员需要在“系统管理 → 用户管理”中为目标账号打开“客户端灰度”；打开后只显示网页中的下载、实例状态、本地工作区和“个人设置 → 本地 OpenCode 客户端”，不会自动安装、启动或连接客户端。未开放账号看不到这些入口。

![个人设置中的本地 OpenCode 客户端区域：Client key 为掩码显示，在线客户端会展示连接状态](./images/operations/settings-local-client-key.png)

**怎么用：**

1. 已开放账号打开“设置 → 个人设置 → 本地 OpenCode 客户端”，创建并立即保存只显示一次的 Client Key。
2. 点击右上角头像，在 OpenCode 实例列表下方选择“下载本地客户端用户包”；当前只支持麒麟 ARM64。
3. 完整解压用户包，双击 `TestAgent-Local-Client` 并按提示输入 Client Key；安装只写当前账号目录，不需要 sudo。客户端在线后，从系统托盘选择“选择并注册工作区…”，在系统目录窗口中选中项目目录；目录名会成为默认工作区名称，原目录不会被复制或改动。
4. 注册成功会自动打开对应工作台；未自动打开时，点击托盘“打开网页”，再从顶部“工作空间 → 本地工作区”打开已注册目录。客户端下载按钮会在客户端在线后隐藏，网页改为显示本地 OpenCode 健康度。

关闭“客户端灰度”只隐藏网页入口和本地工作区投影，不会停止客户端、重启本地 OpenCode 或撤销 Client Key；若当时正使用本地工作区，页面会优先恢复进入本地前的服务端工作区。完整操作和 Key 安全提示见[设置与权限内操作](./settings.md#普通用户个人设置)。

### 自动化代码库改为工作区内只读参考

**适用场景：** 在当前测试工作区中参考同一应用的自动化脚本，但不修改或切换进自动化仓库。

**入口在哪：** 进入测试工作空间后，左侧组合文件树根部会出现虚拟目录“自动化代码库”。顶部和左下角的主工作空间菜单不再列出自动化仓库。

**普通用户怎么用：**

1. 选择应用并进入一个测试工作空间。
2. 展开左侧“自动化代码库”，再展开需要参考的自动化配置。
3. 文件可以只读打开、下载或加入对话；不能编辑、上传、删除、移动、搜索或执行 Git 操作。
4. 管理员保存新的分支或目录后，新展开或刷新使用新 generation；已经打开的标签和运行中的任务继续使用原 generation，关闭后重新打开或新建任务才更新。

![页面顶部只保留主工作空间入口，自动化代码库从左侧组合文件树展开](./images/operations/automation-workspace-switch.png)

**使用前配置（应用管理员或超级管理员）：**

1. 点击页面左下角齿轮“设置”。如果还没有 SSH Key，点击左侧“个人设置”，填写“SSH Key 名称”和“私钥内容”，再点击“添加 SSH key”。
2. 点击设置左侧“版本库管理”，再点击“已有版本库”右侧的“新增”。依次选择部署模式，填写版本库地址、名称和英文名称，把“版本库类型”选为“自动化代码库”，最后点击弹窗右下角“新增”。
3. 点击设置左侧“应用管理”，在页面上方“应用选择”中选中目标应用，再点击“应用与版本库关联”。从“选择未关联版本库”下拉框选中刚才的自动化代码库，点击“关联”。
4. 返回工作台并进入一个测试工作空间，打开“引用配置”，切换到“自动化代码库”；左侧每张卡片就是一个已关联的自动化版本库，点击卡片只会选择，不会自动拉取。
5. 依次选择版本库、一个分支和仓库根或任意已有目录；描述会自动填充，也可以修改。点击“保存”后平台才准备共享副本并整体生效。每个版本库始终只有这一套当前配置，普通用户在该页只读查看。

![版本库管理中已经登记为自动化代码库的仓库](./images/operations/automation-repository-config.png)

自动化代码库允许选择远端树中的任意已有目录，但不能在该表单中新建目录；文件也不能作为配置根目录。平台为每台服务器维护共享只读仓库副本，不再为用户创建自动化个人 worktree。完整字段和权限见[引用配置](./reference-config.md)与[应用版本与个人工作区](./workspace.md)。

如果文件树没有“自动化代码库”，先确认当前是该应用的测试工作空间；仍未出现时，通常是管理员尚未保存自动化配置，或当前 generation 的本机副本尚未就绪。不可用引用会被省略并显示局部告警；主工作区和其它有效引用不受影响。

### 分享会话后，系统会直接通知同事

**适用场景：** 请同事评审结果、交接一个长任务，或让另一位成员在原上下文和原工作区中继续处理，不再手工复制聊天记录和文件路径。

**使用前配置：** 不需要平台管理员额外开通。分享人和被分享人都要有可登录的平台账号；分享人只需在当前会话中选择成员、有效期和权限。被分享人无需配置工作空间，进入后使用的是分享人的固定会话和工作区。

**怎么用：**

1. 在已有会话右上角点击“分享”，选择 1 天、3 天或 7 天有效期。
2. 添加平台用户，并逐人设置“只读”或“可对话”权限后保存。
3. 被分享人会在顶部通知铃铛中收到提醒；点击有效通知会在新标签页打开会话，成功进入后通知才变为已读。
4. 没看到通知时，可从“会话列表 → 分享给我”查找。需要收回权限时，由分享人再次打开分享设置并取消分享。

![会话分享时配置成员、可对话权限和三天有效期](./images/operations/session-share-config.png)

![被分享人在通知中心收到可点击的会话通知](./images/operations/notification-center.png)

“可对话”成员使用的仍是分享人的会话和工作区，页面会记录实际操作人；同一条分享会话同时只能执行一个任务。完整协作边界见[对话与上下文](./conversation.md#把会话分享给同事)。

### 一次带多份测试资料去关联页面

**适用场景：** 测试设计或测试执行资料分散在多个文件中，需要一次带到关联的需求、案例或执行页面继续处理。

**使用前配置：** 普通用户无需逐个文件配置，只需确认文件位于“测试设计”或“测试执行”目录。平台交付管理员需要在前端构建配置中提供 `VITE_CACHE_DATA_URL`，指向受控的资料缓存服务；页面提示“缓存数据地址未配置”时，联系管理员处理。浏览器还需要允许当前站点打开新标签页。

**怎么用：**

1. 在工作空间文件树中按住 `Ctrl`（Windows）或 `Cmd`（macOS），选择多个文件或目录。
2. 点击工作空间标题右侧带数量的纸飞机按钮“缓存并跳转”。
3. 新标签页打开后继续处理；原文件不会被移动、改名或删除。

![在测试设计目录中多选两份资料后出现数量为二的纸飞机按钮](./images/operations/multi-select-materials.png)

测试设计只支持文件，测试执行支持文件和目录。一次建议只选择同一类资料；路径中的 `S-数字` 子条目编号会一并带过去。更多限制见[应用版本与个人工作区](./workspace.md#把测试资料带到外部页面)。

### 一次提交 SkillMarket 材料并自动刷新目录

**适用场景：** 超级管理员已经准备好可公开复用的 Skill 包和审查证明，希望把它提交到外部 SkillMarket，而不是手工等待目录同步。

**使用前配置：** 只有超级管理员能看到“上传 Skill”。准备根目录包含 `SKILL.md` 的 Skill ZIP，以及安全审查报告、目录结构、运行效果三张已脱敏 PNG/JPG 图片。不要提交 Token、Client Key、账号、客户数据或内部绝对路径；该上传不会写入当前应用或个人 worktree，也不会替代应用内 Agent/Skill 的 Git 发布。

**怎么用：**

1. 从左侧活动栏打开“Agent / Skill / MCP / Tool Hub”，切换到“Skill”，点击右上角“上传 Skill”。
2. 填写技能提供方，选择 `00·通用` 至 `06·运维` 中对应的所属阶段，再选择 ZIP 和三张必需图片。
3. 点击“开始上传”，在弹窗中查看任务 ID 和实时进度。成功后，平台自动同步能力库并刷新 SkillMarket 列表。
4. 100 秒内没有最终结果时，点击“继续查询”；不要重复上传。若已提示上传成功但目录同步失败，等待后台定时对账后再点“刷新目录”。

### 本地客户端失败时导出受限诊断日志

**适用场景：** 客户端在首次安装、接入、重连、更新或启动本地 OpenCode 时失败，需要让管理员按同一时间窗定位问题，同时不暴露凭据或工作区内容。

**使用前配置：** 当前客户端已经安装并能显示系统托盘 TestAgent 图标；客户端灰度仍只决定网页下载、实例状态和本地工作区等入口是否可见，不会替用户自动安装或启动客户端。

**怎么用：**

1. 点击系统托盘 TestAgent 图标，先选择“查看日志”确认失败时间和提示。
2. 需要上报时，在同一弹层选择“下载日志”。客户端会在本机下载目录生成 ZIP 并打开文件位置。
3. 把失败时间、操作和页面或托盘提示与 ZIP 一并交给管理员；管理员应使用其中的 `session`、`traceId`、`failureCode` 和时间窗关联平台记录，而不是索取 Client Key。

下载包最多包含 20 个客户端或启动器日志，每个文件仅保留末尾最多 10 MiB，不含 Client Key、认证头、配置、`opencode.log`、提示词、请求正文或工作区文件。当前没有托盘“查看日志 / 下载日志”流程的脱敏真实截图；需要人工补拍托盘弹层及生成 ZIP 后的文件定位状态。完整边界见[设置与权限内操作](./settings.md#客户端无法连接安装或更新时查看并导出诊断日志)。

### 公共 Agent 发布后按进程有界并行排空

**适用场景：** 超级管理员已发布公共 Agent、Skill 或 Tool 配置，希望确认所有服务器完成同步，并让旧用户进程在不打断运行中会话的前提下加载新配置。

**使用前配置：** 仅 `SUPER_ADMIN` 可进入“系统管理 → 配置管理 → TestAgent公共配置管理”。先确认目标公共分支和共享运行副本中的本地变更是否允许清理；个人 worktree 的未覆盖改动会按 Git 原生 merge 保留，存在覆盖风险或冲突的用户需先处理其 Diff。

**怎么用：**

1. 打开“TestAgent公共配置管理”，选择远端公共分支，点击“刷新公共 Agent Git”。平台先固定目标 commit，再同步各服务器的共享运行副本。
2. 在服务器进度中查看 Git 同步、旧进程排空、个人 worktree 待处理数、重试次数和 `last_error`。不同用户进程会有界并行排空；同一进程上的多个配置目标保持顺序执行，避免重复释放或重启。
3. 运行中的会话不会被强行中断。相关用户可能短暂看到“配置更新正在排空旧运行态”，应等待当前任务结束和运行态重载，不要反复启动进程或重复点击刷新。
4. 任务进入完成或终止状态后再处理异常：对冲突的个人 worktree 在“变更”中完成 Diff/合并，平台会自动重试；其他服务器和用户不受该单个冲突阻塞。

当前没有“TestAgent公共配置管理 → 刷新公共 Agent Git”与进程排空状态完全一致的脱敏真实截图；需要人工补拍包含刷新按钮、服务器进度和用户进程状态的同屏页面。完整权限和数据边界见[设置与权限内操作](./settings.md#超级管理员刷新公共-agent-git)。
:::

详细权限、材料格式和数据边界见[Agent 与 Skill 配置](./agent-config.md#向-skillmarket-上传-skill)。
