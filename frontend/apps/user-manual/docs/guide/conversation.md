# 对话与上下文

右侧对话区用于发起测试任务、查看执行过程和处理 Agent 的交互请求。第一条消息发送时会自动创建主对话。

## 对话到底怎么建？

正常流程不需要先建会话：选中应用和 workspace、确认 TestAgent 服务可用后，在输入框写任务并点击发送，系统会在发送时自动创建主对话并把第一条消息作为标题来源。

右侧输入卡片的“新建对话”图标用于主动清空当前草稿、开始另一条对话。它不会删除历史对话，也不会取消后台已经运行的任务；历史对话仍可从历史入口找回。

## 怎样写清楚任务

一条可执行的任务通常包含四部分：

1. 测试对象：哪个需求、接口、模块或文件。
2. 动作：分析、设计案例、执行测试、修复问题或审核结果。
3. 约束：使用哪些材料、目录、格式或测试方法。
4. 产物：结果写到哪里，需要哪些文档或代码。

## 把会话分享给同事

需要同事一起看结果或接着处理任务时，可以直接分享当前会话，不用复制聊天记录和文件路径。分享只对你选中的平台用户生效；别人拿到链接但不在名单里，仍然打不开。

### 我来发起分享

1. 打开要分享的已有会话，点击对话区右上角的“分享”。
2. 选择 1 天、3 天或 7 天有效期，再按姓名或统一认证号搜索同事。每条会话最多可添加 50 人。
3. 为每个人选择权限：“只读”只能查看；“可对话”可以在这条会话里继续发消息和处理文件。
4. 保存后，系统会直接通过右上角通知铃铛提醒被分享人，无需再手工发送地址。以后调整名单、权限或有效期时仍使用同一份分享；新的有效期从本次保存时重新计算。

分享设置较多时，可以拖动弹框右下角调整宽高。只有站内通知暂时不可用时，才使用弹框页脚低强调的“复制备用链接”；唯一链接仍会保留，但不再作为正常分享步骤。

![协作分享弹框中配置三天有效期、被分享人和只读或可对话权限](./images/operations/session-share-config.png)

自己的会话列表会用分享图标标出已经分享的会话。有效分享使用彩色图标，过期或取消后变为灰色。需要立即收回权限时，再次打开“分享”并点击“取消分享”。原链接会保留，之后重新启用即可继续使用。

如果会话里还有待执行的定时任务，取消分享不会取消这些任务。任务仍会按原计划、以会话所属人的身份执行；不再需要时，请另行到“会话列表 → 待执行任务”中取消。

### 我收到别人分享的会话

1. 点击工作台右上角的通知铃铛。面板默认展示“未读”，“全部”位于后一个标签；红色闭合信封表示未读，灰色打开信封表示已读，未读取就已经过期或撤销的记录使用停用图标。“会话列表 → 分享给我”继续作为备用入口。
2. 点击有效通知或状态为“有效”的分享会话，系统会在新标签页打开。成功进入后通知才会变为已读；已过期、已取消、已移除或已归档的记录会保留为灰色，不能再进入。
3. 如果权限是“只读”，可以查看消息、执行过程、文件和变更，但不能发送消息或修改文件。
4. 如果权限是“可对话”，普通用户仍不能切换模型；只有超级管理员在工作台连续独立按三次 Ctrl 后，才会显示模型选择入口并可切换。这里固定使用分享人的会话和工作区，产生的文件改动也会落在该工作区；页面会保留实际操作人的姓名，方便大家分清是谁发起的操作。

分享会话同一时间只执行一个任务。只要有一位参与者正在运行任务，其他人就要等它结束，不能再发送或排队。需要开始自己的任务时，可点击输入框右侧的“新建对话”直接返回本人工作台。分享过期、被取消或你被移出名单后，当前分享页会立即变成失效状态。

![通知中心显示别人分享的对话、可对话权限和到期时间](./images/operations/notification-center.png)

## “上下文已压缩”是什么？

长对话接近模型上下文容量时，可以输入 `/compact`（或 `/summarize`）把较早的内容整理成一份续写摘要。执行期间，输入框上方会持续显示“正在压缩上下文”的收拢动画；压缩和消息刷新结束后会原位切换为“上下文压缩完成”，因此不需要靠刷新页面判断进度。压缩进行态不会在时间线中再增加一条记录；摘要完成后，时间线只新增唯一一条“上下文已自动压缩”或“上下文已手动压缩”结果按钮，不会并入思考状态按钮。摘要默认收起且不会平铺，点击按钮后才在下方展示摘要本身。分享会话中的其他参与者会自动看到压缩结果，不需要刷新页面。

摘要中的“当前目标”是正在完成的任务；“关键信息”保存约束、偏好和已确认的决定；“工作状态”再分为“已完成 / 进行中 / 阻塞项”；“下一步”表示恢复任务后优先执行的动作；“相关文件”列出需要继续使用的文件。显示“无”只表示该栏当时没有可记录内容。

## 怎样看任务耗时和记忆使用

对话底部的“任务消耗”会在任务运行时持续累计耗时，并在有数据时同时显示 Token。任务结束后，当前页面不会把已经显示的耗时清掉。夜间任务即使跨页面执行，刷新页面或重新打开对应历史会话时，也会按已有运行记录恢复最终耗时，不会只剩 Token。

成功结果旁可能出现“参考了 N 条记忆”。这表示系统确实把这些长期记忆用于了本轮任务；没有显示时，只代表本轮没有实际使用记忆。个人记忆、团队记忆和来源证据的管理方法见[长期记忆](./memory.md)。

## 安排夜间执行

算力紧张时，可以把任务安排在北京时间晚上 9 点到次日早上 7 点异步启动：

1. 先在当前消息框写好任务，并按需添加 Agent、文件或需求子条目；模型切换入口仅对完成隐藏手势的超级管理员显示。
2. 点击发送按钮左侧的定时图标。
3. 在 15 分钟启动时段中选择一个时间。系统会根据全局名额自动标出推荐时段；显示“已满”的时段不能选择。
4. 确认后等待“已安排”提示。只有提交成功后，草稿和上下文附件才会清空。

当前已经打开历史对话时，任务会在该对话继续；处于全新空白对话时，系统会为任务预留一条新对话。弹层不再单独询问执行位置。

点击对话栏顶部的“会话列表”，在左侧浮层中切换到“待执行任务”，页面会立即刷新并分页收齐自己所有尚未启动的夜间任务。当前对话的任务排在最前，其余按启动时段排序。任务卡会显示内容预览、启动时段、创建时间、状态以及发生过的顺延次数；任务仍为“待执行”时可以改期或取消，进入“正在启动”后不能再改期或取消。取消前需要在卡片内再次确认。

已有对话安排夜间任务后，在任务取消、最终失败或成功启动前，当前对话不能继续发送普通消息，也不能归档；“新建对话”仍可使用，可以先处理别的工作。任务启动后直接复用普通对话的执行过程和结果展示，用户消息旁会显示“夜间定时执行”和北京时间的实际启动时间。如果窗口内始终无法启动，当前对话会显示失败卡；关闭失败卡不会重新执行任务。

夜间任务已经启动后，如果模型在根会话返回错误，平台会自动尝试撤销并重发最后一条用户消息，最多 3 次，分别等待约 1、2、4 分钟。
等待时消息旁显示“自动重发 n/3”和倒计时，对话输入会暂时锁定；替代消息开始后，旧回答、工具过程和文件改动会按原生回退语义移除。
第三次仍失败时保留最新失败轮次和“3/3”标识。自动重发不会由手动操作重置。

普通对话、夜间对话或分享对话的最后一条用户消息，在运行已经结束且仍可安全恢复时，只有这条消息的实际发送人会看到“撤销重发”；分享发送人还需要保有对话权限。会话所属人如果不是发送人，也不能撤回或改写别人发送的消息。点击后，上一条消息会先回到输入框并显示“正在修改上一条消息”；可以直接发送，也可以修改后再发送，点“取消”则保留原对话不变。请求失败时修改内容不会丢失。

确认发送后，原用户气泡会立即显示修改后的文字，状态栏进入运行中；旧回答、工具过程、Todo 和 Diff 同时从页面隐藏，但该用户消息保留在原位置，附件、Agent 和模型选择继续复用。如果原生回退开始前失败，旧内容会恢复，否则随后由新结果继续展示。平台使用新的消息标识重新执行，权威消息到达后仍在原位置接管，不会同时显示新旧两个气泡。共享会话里的其他参与者会自动看到修改和新结果；如果重发被取消或失败，原消息和回答也会原位恢复，不需要刷新或重新进入会话。旧回答不会继续进入模型上下文；运行中、子 Agent、较早消息或缺少远端边界时不显示该入口。OpenCode 自身的短时“重试中”只表示模型供应商重试，
页面会展示状态但不会因此重复发送消息。

## 批量生成子条目测试案例

鼠标移入右侧输入卡片，或把光标放进输入框后，卡片上沿会显示“批量生成子条目测试案例”图标。点击后可在页面弹层中一次选择多个当前 workspace 的需求子条目：

1. 列表与输入框键入 `#` 时完全相同，可按需求项或子条目名称搜索，也可全选；一批最多选择 50 项。
2. 底部要求默认为“请生成子条目测试案例。”，可以修改；系统会自动为每项补充需求项和子条目名称。
3. 选择“立刻执行”时，每个子条目都会建立一条独立对话并立即运行，不会切换或清空当前对话。
4. 点击“选择定时”后，立即执行入口会隐藏；可以勾选多个可用夜间时段，系统按子条目顺序轮流分配，超级管理员还可添加未来 24 小时内的多个整分钟测试时间。选中有效时间后，原主操作位置才会显示“定时执行”；夜间总剩余名额不足时不能提交。定时区域右上角的关闭图标可返回立即执行模式，并丢弃尚未提交的时间选择，但不会清空已选子条目或生成要求。
5. 点击“立刻执行”或“定时执行”后，弹层会立即切换到不可编辑的“会话创建情况”页，不能再次提交同一批次；每行会显示资料加载、会话创建、启动或任务创建结果。
6. 创建情况页不会自动关闭。其他条目不会因为单项失败而停止；失败项可单笔重试，也可批量重试全部失败项，重试会沿用本次批量身份和已经创建的会话。
7. 创建或重试期间不能关闭。处理结束后由你主动关闭；若还有条目没有创建会话，页面会先确认是否结束本次批量创建。确认关闭后本批次结束，再次打开时选择为空且要求恢复默认值。

每个子条目会读取 `#` 候选聚合出的需求、设计、编码和测试阶段文件。二进制文件会跳过；无可读文件、读取失败或内容超限的条目不会创建对话。批量资料使用独立上下文，不会出现在当前输入框的附件区。

批量资料沿用工作台对话上下文的前端容量规则：单个文本文件最多 80,000 个字符，同一子条目的全部文本文件合计最多 120,000 个字符，批量生成要求最多 20,000 个字符。这里统计的是浏览器读取到的文本长度，不是模型 Token 数；超过限制只会让对应子条目失败，不影响其他条目继续执行。

## 添加上下文

- `@Agent`：选择当前运行态已经加载的 Agent。双语模板候选项以中文名为主、英文名为辅，选择后仍插入稳定的 Agent 英文技术 ID。
- `/Skill`：选择当前 Agent 可用的 Skill。双语模板候选项同样以中文名为主、英文名为辅，选择后仍插入稳定的 Skill 英文技术 ID。
- `@文件`：选择工作区文件并作为显式上下文加入本轮消息。
- `#需求子条目`：只解析 `spec/<需求项>/<阶段>/<子条目>` 结构，按同名子条目聚合需求、设计、编码和测试阶段文件；工作区根目录下的旧需求结构不会进入候选。
- 小地球引入：先在左侧“工作空间”标题右侧点击小地球，从外部需求页面引入子条目；返回后再用 `#` 选择，避免只把单个阶段文件漏带进任务。
- 编辑器选区：把当前选中的代码或文本加入下一轮消息。
- Git hunk：从差异视图引用当前变更片段。

通过聊天附件按钮选择的文件会先保存到当前个人工作区：内容和扩展名一致的文件自动复用，文件内容变化时保留新版本，不覆盖历史对话引用。文本和代码由 OpenCode 原生读取；图片、PDF、音频和视频会根据当前模型能力决定是否原生读取；Excel、Office、压缩包及模型不支持的媒体交给工作区工具处理。附件较多时页面只折叠展示，不会减少本轮实际关联的文件。

新建或修改 Agent/Skill 定义后，平台会自动热加载当前用户目录；重新输入 `@` 或 `/` 会按最新目录给出候选。`@` 遵循 OpenCode 原生子智能体口径，只列出 `subagent`/`all`，因此默认 `primary` Agent 不在其中；`/` 只列出 OpenCode 已识别且当前 Agent 有权使用的 Skill。

## 处理中可以做什么

- 当前 Run 忙碌时继续发送的 Prompt 会进入跟进队列。
- Agent 出现权限卡时，按本次允许、始终允许或拒绝作出选择。
- Agent 出现提问卡时填写答案，提交后原卡片会收敛为完成态。
- 需要终止时使用停止按钮；只有 Run 已创建并处于运行态时可以终止。

## 小宠物旁路问答

主对话至少发送过一条消息后，点击小宠物会基于当前主 Session 创建临时上下文，不写入主对话历史，适合追问“刚才做了什么”“为什么失败”。

小宠物提供寻迹鹿、巡查红熊猫、深夜龙、星探狐、稳态熊猫、工具浣熊和夜巡猫七种图片形象。打开宠物浮层后，点击标题栏的脚印按钮可以选择显示方式：

- 每日轮换：按本地日期依次更换值班伙伴。
- 每天随机：每天抽取一个伙伴，当天保持不变。
- 自主选择：固定使用自己选中的伙伴。

在同一处可以用“宠物大小”滑杆调整显示比例（75%–250%，默认 150%）。比例保存在当前浏览器，旧版本没有该设置时按 150% 显示。

显示偏好只保存在当前浏览器，不会影响旁路问答内容，也不会同步到其他设备。

帮助中心中的“小宠物问答”会携带当前手册章节，适合询问按钮含义和操作顺序。没有主对话时，只要已经选择工作区且 TestAgent 服务可用，小宠物就会创建独立的内部手册问答 Run；它不会创建普通聊天会话，也不会把问题或答案写入主对话历史。

## 会话列表

点击对话栏顶部的“会话列表”，会在对话栏左侧打开非模态浮层，主对话仍完整可见。“我的会话”可以搜索和连续切换已有会话，当前会话会高亮；“分享给我”集中显示其他用户分享的会话；“待执行任务”用于管理还没启动的定时任务。选择自己的会话后浮层不会自动关闭，便于继续查找。点击会话卡片右侧的图钉可以置顶，再次点击即可取消置顶；置顶会话集中显示在普通会话之前，两组内部都按最后更新时间倒序，取消置顶后会回到普通会话的时间排序。再次点击“会话列表”、点击关闭按钮、按 Esc 或收起整个右侧对话栏时会关闭浮层。

切换尚未完成时不要重复发送消息；只读历史会明确显示原因。新建对话只清理当前草稿，不会删除历史 Session。
