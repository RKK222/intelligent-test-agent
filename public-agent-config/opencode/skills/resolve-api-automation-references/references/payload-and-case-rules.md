# 报文与全案例生成规则

## 全案例覆盖

- 执行范围内每个已评审接口案例必须生成一个独立接口自动化脚本；
- TCDS、TC 和一体化平台返回数量只决定参考集合，不决定输出数量；
- 没有直接参考的异常、空值、枚举、长度和边界案例，使用最相关成功参考作为基准，只修改案例指定字段；
- 不得用“同上”“类似案例”“其余字段不变”代替完整请求报文或必要断言。

## 请求结构

一体化平台存在非空 `reqParamStruct` 时：

1. `reqParamStruct` 数组中唯一的第一层节点默认是结构根节点，只描述报文外壳，不是实际请求字段；生成报文不得输出该节点名称，直接把它的 `children` 作为报文第一层字段。根节点无论名为 `ROOT`、`Request`、接口名或其它值都按此规则处理；
2. 默认递归创建根节点 `children` 下的全部对象、数组和叶子字段；仅已评审案例明确要求缺少或新增字段时，按下述“结构增删案例例外”处理；
3. 非缺字段目标的空值字段也必须保留，字符串空值写 `""`，不能删除或写 `null`；
4. TC/上传参考中不存在的结构字段按同接口最高优先级参考填值；仍无值时按 `reqParamStruct` 递归补齐全部后代字段，叶子字符串为 `""`；只有结构字段本身确为可空数组且当前案例无元素时才使用 `[]`，不能用空对象省略其子字段，也不能把参考本身缺字段误当成当前案例允许缺字段；
5. 参考中多出的字段默认不得加入最终报文；只有已评审案例明确测试新增该字段时，才允许把案例指定的精确路径加入。允许列表必须来自案例，不能来自参考本身；把第一层根节点名称写入报文仍属于禁止的额外字段；
6. 结构字段顺序遵循第一层根节点 `children` 的返回顺序；案例明确新增的字段放在案例指定父容器的原结构字段之后，多个新增字段按案例顺序；
7. 生成后必须运行 `scripts/validate_generated_payload.py`。普通案例传空的 `expectedMissingPaths` 和 `expectedAdditionalPaths`；结构增删案例分别传精确字段路径。失败时修正并重新验证。

例如结构为 `ApiRequest -> ACCOUNT, EMPTY` 时，正确报文是 `{"ACCOUNT":"1234","EMPTY":""}`，不能生成 `{"ApiRequest":{"ACCOUNT":"1234","EMPTY":""}}`。

如果某个 Map 字段的实际值是 XML 字符串，校验器会继续按其 children 校验 XML 元素结构；不能因为外层是字符串而跳过内部字段检查。

## 结构增删案例例外

- `reqParamStruct` 是默认结构权威。案例没有明确结构增删要求时，最终报文必须与其完全一致，不能多也不能少；普通案例的 `expectedMissingPaths` 和 `expectedAdditionalPaths` 都必须为空；
- 只有当前已评审案例明确把“缺少、不传、删除某个字段”作为测试动作时，才允许该案例少字段。从案例原文和 `reqParamStruct` 映射出精确路径写入 `expectedMissingPaths`；字段必须在最终报文中实际缺少，仍存在（包括值为 `""` 或 `null`）、路径不属于结构，或同时缺少列表之外的字段，校验均失败；
- 只有当前已评审案例明确把“新增、多传、传入未定义字段”作为测试动作时，才允许该案例增加字段。从案例原文映射出精确路径写入 `expectedAdditionalPaths`；路径本身必须位于 `reqParamStruct` 之外，父路径必须是结构中已有容器或报文顶层。新增对象只声明其新增根字段，不能用 `NEW.child` 绕过父路径检查；
- `expectedAdditionalPaths` 中的字段必须在最终报文中实际出现，值按案例要求填写；案例只要求新增但未指定值时，沿用最高优先级参考中的对应值，不输出占位语。案例要求空字符串时仍显式输出 `""`，不能因值为空省略字段；
- 缺字段目标为对象或数组节点时允许省略该节点及其整个后代；目标为数组元素内字段时，每个实际数组元素都必须省略。新增目标位于数组元素内时，每个实际数组元素都必须包含；
- 缺字段和新增字段可以在同一案例同时生效。两类允许列表都必须在生成前从已评审案例原文提取，不得观察生成结果后补录，也不得根据 TC 或一体化平台参考偶然存在的结构差异扩大列表；
- 除案例明确指定的缺失和新增路径外，其余字段、嵌套关系和空字符串仍必须与 `reqParamStruct` 完全一致；任何未声明额外字段、声明但未生成的新增字段、把已有结构字段声明为新增字段或无效新增父路径都会导致校验失败。

## 长度案例

案例涉及长度、最大长度、最小长度、超长、不足或精确位数时：

1. 从已评审案例取得目标字段、期望长度和计量方式；
2. 生成报文后从最终序列化报文重新读取实际值；
3. 使用 `validate_generated_payload.py --length-check <path>=<length>:chars` 校验字符数；案例明确要求 UTF-8 字节长度时使用 `:utf8-bytes`；
4. 校验失败必须修改实际值后重跑，不能只修改脚本中的文字说明；
5. 中文、代理对和转义字符按指定计量方式计算，不按 Markdown 源码长度计算。

## 数据准备与断言

- 数据准备可以是平台返回的 SQL 或 table 数据，保持原格式，不互相转换；
- 所有适用于当前案例的准备和恢复动作必须完整保留并按执行顺序输出，不能只选一条代表性 SQL；
- SQL 必须逐字符保留参考中的完整语句，除跨平台换行统一外不得截断、摘要、重排、合并、拆分或重新格式化；长度不是跳过理由；
- table 必须保留全部表名、操作类型、列、行、顺序和空值，不能裁剪大表或只保留示例行；
- `stepType=0` 为准备，`stepType=1` 为恢复；`executeTiming=0` 为每案例前，`1` 为全部案例前；
- `caseIdList=all` 时应用 `excludeCaseIdList` 排除；其它值按逗号分隔精确关联；
- 返回断言、数据库断言和 Mock 同样按 caseId 适用范围映射；
- 异常案例复用成功参考时，必须调整与目标异常字段直接相关的预期返回和数据库断言；无直接关系的准备和断言保持参考一致；
- 禁止编造外部表名、SQL 字段、返回码和 Mock 返回。关键执行事实完全无法恢复时返回 `INCOMPLETE`，不要输出占位语。

## 禁止词

进入接口 ID/英文名参考分支后，正式脚本不得包含：

```text
待确认
需确认
未确认
TBD
TODO
```

不确定但存在参考值时保持参考值；不存在可执行基准时阻断生成。
