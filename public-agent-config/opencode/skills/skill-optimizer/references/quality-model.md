# Skill 质量模型

## 评审维度

| 维度 | 核心问题 | 可观察证据 |
| --- | --- | --- |
| 触发召回 | 真实需要时是否会触发 | 多种说法、隐含意图和少见场景的触发结果 |
| 触发精度 | 相邻任务是否被错误截获 | 近似但不应触发的查询结果 |
| 任务正确性 | 是否按输入和约束完成目标 | 文件、结构、断言、工具输出和业务评审 |
| 稳定性 | 边界和失败时是否行为一致 | 缺失输入、权限不足、工具失败和重复运行结果 |
| 交付诚实 | 是否区分已验证、未验证和假设 | 最终说明与真实命令记录的一致性 |
| 效率 | 是否存在无效步骤和重复上下文 | 耗时、token、工具次数、重复读取和重复生成 |
| 可维护性 | 规则是否单一、清晰、可定位 | 重复段落、冲突指令、失效引用和文件规模 |
| 展示兼容 | 中文展示与英文技术 ID 是否解耦 | 双语 description、display metadata、目录和顶层 name |
| 安全性 | 是否守住权限和敏感数据边界 | 危险操作确认、脱敏、目标校验和失败停止 |
| 可移植性 | 是否可在目标企业环境运行 | 公网、个人路径、依赖、版本和平台差异检查 |

## 根因分类

### 描述问题

- 只有能力名，没有用户会说的任务语境；
- 关键词过宽，把近邻技能或普通问答一起触发；
- 缺少隐含意图、文件类型或目标产物；
- 与相邻技能边界相互重叠或互相留空。

### 流程问题

- 缺少输入门禁，导致在关键事实不足时继续编造；
- 只有理想路径，没有权限、工具失败和停止条件；
- 输出格式存在多个互相冲突的定义；
- 规则强调动作但未解释目的，遇到新场景无法泛化。

### 资源问题

- `SKILL.md` 承载全部低频资料，触发后上下文过重；
- 正文只列文件名，没有说明何时必须读取；
- 多个规则或模板复制相同事实，版本容易漂移；
- 每次执行都临时重写同一确定性脚本。

### 验证问题

- 只测试一个理想示例；
- 断言检查格式，不检查用户真正关心的结果；
- 候选使用了比基线更多输入、工具或人工提示；
- 只报告均值，不检查失败样例和波动；
- 测试提示被原样硬编码进技能。

## 优先级

1. 安全、越权、数据泄露和不可恢复操作；
2. 错误结果、虚假完成和兼容性破坏；
3. 高频误触发、漏触发和流程不稳定；
4. 输出质量、效率和可维护性；
5. 低频表达和非关键样式。

## 通过标准

优化版本只有同时满足以下条件才能作为可交付版本：

- 约定的主要失败场景已在候选版中得到验证；
- 原有关键成功场景没有回归；
- 名称、目录和公开契约的变化已明确处理兼容性；
- 中文展示名已补齐，英文目录和顶层 `name` 未因展示调整而变化，已有 `metadata.source` 保持真实来源；
- 结构校验和测试数据解析通过；
- 所有未运行项和剩余风险已如实列出。
