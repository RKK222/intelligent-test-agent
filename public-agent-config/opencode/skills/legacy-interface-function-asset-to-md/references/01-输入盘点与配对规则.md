# 输入盘点与配对规则

## 1. 文件角色识别

| 类型 | 识别方式 | 常见内容 |
| --- | --- | --- |
| 测试脚本 | 扩展名、测试注解、测试入口 | 接口调用、请求构造、SQL、Assert |
| 测试数据 | 多行参数、案例 ID、预期值 | 场景差异、请求初值、预期结果 |
| 框架配置 | Sheet/配置键、生命周期、开关 | SQL、断言、Mock、环境 |
| 接口文档 | 服务/URI、输入输出、版本 | 契约补充 |
| 测试案例 | 案例编号、步骤、预期 | 测试意图补充 |
| 执行日志 | 请求/响应、SQL、Mock 命中 | 验证执行性和运行时值 |

## 2. 配对评分

- 脚本显式引用数据文件：+100；
- 测试类名与数据文件主名一致：+60；
- DataProvider 与 Sheet/配置一致：+40；
- 接口方法或 URI 一致：+30；
- 案例 ID 集合相交：+20；
- 仅语义相似：+10。

只有最高候选明显领先且没有反证时才自动配对。候选接近时列出全部候选及原因。

## 3. 多文件处理

- 多个脚本调用同一 `interface_key`：合并为一个功能资产，并在内部保留全部输入的映射；
- 一个数据文件供多个脚本使用：按代码真实读取字段拆分；
- 一个脚本调用多个主接口：按主接口拆分；
- 公共工具类只作为来源，不单独产出资产。

## 4. 内部输入指纹

每个输入文件可在内部记录：

```text
path
size
sha256
parser_name
parser_version
```

不得只记录一个无法追溯到具体文件的组合指纹。路径、指纹和配对证据仅用于内部刷新与判断，不写入正式资产或转换报告。
