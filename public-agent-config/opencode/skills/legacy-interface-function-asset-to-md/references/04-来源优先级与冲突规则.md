# 来源优先级与冲突规则

## 1. 按信息类型选择主证据

| 信息 | 主证据 | 补充证据 |
| --- | --- | --- |
| 实际接口调用 | 可达代码/流程 | 文档、配置 |
| 调用顺序 | 可达代码、生命周期 | 日志 |
| 场景初始输入 | 配套测试数据 | 报文样例 |
| 运行时最终输入 | 代码覆盖和表达式 | 日志 |
| 实际断言 | 可达 Assert、已确认框架断言 | 测试案例预期 |
| 数据动作 | 可达代码、已确认配置 | 设计说明 |
| 字段契约 | 接口文档/详细设计 | 代码和报文样例 |
| 测试意图 | 精确匹配案例 | 标签说明、方法名 |

## 2. 冲突类型

- `execution_conflict`：两处配置会导致不同执行结果；
- `contract_conflict`：代码字段与文档字段不一致；
- `expectation_conflict`：断言或预期值不一致；
- `scope_conflict`：动作适用场景不一致；
- `duplicate_implementation`：多处维护同类动作；
- `unknown_execution`：存在配置但无法确认是否执行；
- `quality_issue`：乱码、脏字段名、失效路径等。

## 3. 冲突输出

每条冲突至少包含：

```text
severity
conflict_type
description
runtime_impact
recommendation
```

来源对比过程仅保留在内部。`description` 应直接写明相互冲突的值或行为及其差异，但正式资产和转换报告不得输出来源名称、文件路径、代码位置、Sheet/行号、指纹或证据说明。

级别建议：

- 阻断：无法确定主接口或关键输入；
- 高：可能改变执行结果、数据位置或测试结论；
- 中：重复实现、边界不准确、恢复缺失；
- 低：文档质量、命名和非阻断元数据问题。

## 4. 禁止行为

- 不以“文件更新时间较新”直接覆盖另一来源；
- 不以“接口文档更规范”覆盖真实运行字段；
- 不以“Java 中存在”删除 Excel 配置；
- 不以“Excel 中有配置”宣称框架一定执行；
- 不把语义相似测试案例强行映射到存量案例；
- 不擅自修正日期规则、字段名称和错误码。
