# 存量接口自动化资产整理

## 1. 目标与输出

从已有自动化工程中还原真实执行模型。输入完整时，每个实际接口默认且仅生成两个 Markdown：

```text
docs/功能模块/待确认/<接口功能名称>-接口自动化资产.md
docs/功能模块/待确认/<接口功能名称>-资产转换报告.md
```

正式资产必须严格使用 `templates/接口功能自动化资产模板.md`；转换报告必须使用 `templates/资产转换报告模板.md`。

`docs/功能模块/待确认` 是工作空间下写死的相对路径，其中“功能模块”是固定目录名，不得替换成实际模块名称。将运行环境提供的工作空间根目录记为 `WORKSPACE_ROOT`；若环境未提供，则使用任务开始时的工作目录。输出目录固定为：

```text
<WORKSPACE_ROOT>/docs/功能模块/待确认
```

目录不存在时先创建，存在时直接复用。不得将正式输出写入技能目录、输入附件目录、临时目录或旧的 `output/` 目录。除非用户明确要求，默认不生成 ZIP、JSON、TSV、提取报告副本或其他交付文件。

最低输入：

1. 可执行测试脚本；
2. 与脚本配套的测试数据。

接口文档、详细设计、标准测试案例、外部 SQL、Mock 配置和日志均为可选增强输入。缺少任一最低输入时，只生成缺口报告。

## 2. 按需读取规则

执行时按下列条件读取资源，避免重复加载：

- 始终读取 `references/01-输入盘点与配对规则.md`、`references/02-接口功能聚合规则.md`、`references/04-来源优先级与冲突规则.md`；
- 提供 Excel 时，最先读取 `references/00-Excel处理协议.md`；
- 发现 SQL、断言、Mock 或恢复候选时，读取 `references/03-数据准备断言Mock识别规则.md`；
- 生成输出前读取两个模板；
- 交付前读取 `references/05-质量门禁与验收清单.md` 和 `references/06-资产完整性要求.md`。

## 3. 强制执行流程

### 3.1 输入盘点与配对

在内部盘点全部脚本、测试数据和可选输入。根据显式引用、DataProvider、文件名、接口身份和案例 ID 建立配对；无法唯一配对时只在转换报告中说明配对失败或歧义，不输出文件路径和候选来源。

### 3.2 Excel 统一提取

先将本 `SKILL.md` 所在目录解析为绝对路径 `SKILL_DIR`，再执行：

```bash
python "$SKILL_DIR/scripts/extract_excel.py" \
  <测试数据Excel> [接口文档Excel] [测试案例Excel] \
  --output-dir work/excel --debug
```

检查 `extract-report.json`、每个文件的 `summary.md`、`workbook.json` 和 `tables/*.tsv`。后续以这些结果为主要读取来源。

测试数据 Excel 提取失败或结果明显异常时：

1. 停止生成正式资产；
2. 在转换报告中记录提取失败、异常和影响，不输出文件路径；
3. 告知用户需要单独修复 Excel 提取能力；
4. 未经用户明确要求，不修改本技能脚本，也不创建一次性旁路脚本。

CSV 直接按文本读取。

### 3.3 解析测试脚本

提取：

- 测试类、测试方法和 DataProvider/fixture；
- RPC/HTTP 主接口调用、请求构造和返回值；
- 测试数据读取、字段映射、`put/set/builder` 覆盖和条件分支；
- 日期、UUID、流水号、环境变量和类型转换；
- SQL、API、SSH、Shell、文件和公共方法调用；
- Mock 安装、匹配、返回和卸载；
- Assert、JSONPath/XPath、数据库校验；
- setup、teardown、rollback 和 finally。

### 3.4 识别接口并聚合场景

使用 `协议 + 服务/客户端 + 方法或规范化 URI + 版本` 构造 `interface_key`。同一接口的全部参数化数据行和代码分支进入同一个功能资产；一个测试类包含多个主接口时按接口拆分。

### 3.5 还原最终请求

对每个场景按真实顺序计算：

```text
测试数据初值
→ 模板或字段映射
→ 公共运行时覆盖
→ 场景分支覆盖
→ 类型转换和格式化
→ 环境变量替换
```

输出一个包含全量字段的完整请求示例，以及能够重建全部其他场景的场景字段差异。公共字段不再单独输出。

仅在生成资产的 `2.2 完整请求示例` 时，按以下优先级选择基准案例报文；每一级存在多个候选时，选择测试数据原始顺序中的第一条：

1. 优先选择案例名称、标题、说明等描述性文本中具有“调到下游”“调用下游”“成功”等相近正向语义的案例；
2. 第一级未找到时，选择断言中具有“成功”“returncode = 0”等相近成功语义的案例；
3. 前两级均未找到时，使用测试数据原始顺序中的第一条案例。

“成功”必须是正向成功语义，不得将“不成功”“失败”“预期失败”等否定或失败语义识别为成功。该选择规则只决定 `2.2` 的完整请求基准报文，不改变 `2.1` 场景字段差异、`2.3` 请求实现观察或其他章节的生成要求。

生成 `2.2 完整请求示例` 后必须再次核对 key-value 对应关系：

1. 将所选基准案例按“测试数据初值 → 字段映射 → 各级覆盖 → 类型转换和格式化 → 环境变量替换”重新计算为最终字段路径和值；
2. 按完整字段路径逐项比对生成报文中的每个叶子字段和值；嵌套对象、数组下标、XML 元素和属性均分别核对，空值字段也必须保留在原 key 下；
3. 不得依据列序号平移、相邻单元格位置或视觉对齐猜测 value；必须使用字段名、字段路径以及代码中的实际映射关系确定绑定；
4. 同时检查是否存在 key 缺失、重复、串位，或某个 value 被绑定到相邻 key；发现任一问题时立即修正完整请求，并从第一步重新核对；
5. 只有全部 key 均与所选基准案例的最终 value 一一对应后，才可完成并交付 `2.2`。

`2.2` 中的变量表达式必须有代码或 Excel 的明确证据。只有可达代码明确生成或替换该值，或者 Excel 单元格明确写有变量表达式、生成规则时，才保留对应的可执行表达式；否则必须使用 Excel 提取结果中的具体显示值。不得根据字段名称、值的格式或业务含义自行把具体值抽象成变量，例如 Excel 中的时间值 `123045` 必须保持为 `123045`，不得改写为 `${HHMMSS}`。日期、时间、流水号、UUID、随机数和环境值均遵循此规则；即使某个值看起来像动态值，也不得在没有明确证据时自行设计占位符。

### 3.6 发现 SQL、Mock 与断言

同时扫描 Java、生命周期方法、公共方法、Excel 所有工作表、外部文件和日志。按 `references/03-数据准备断言Mock识别规则.md` 判断动作类型、阶段、适用场景和执行状态。

### 3.7 生成资产与转换报告

生成文件前，确认并创建 `<WORKSPACE_ROOT>/docs/功能模块/待确认`。输入完整时，每个接口功能只写入对应的资产 Markdown 和转换报告 Markdown；一个输入包含多个主接口时，每个接口各生成这两个文件。最低输入不完整时，沿用缺口规则，只生成转换报告。

```bash
mkdir -p "$WORKSPACE_ROOT/docs/功能模块/待确认"
```

正式资产只写请求生成模型、SQL、依赖、断言、差异和缺口。转换报告只写汇总、Excel 提取状态、冲突、排除原因和验证结果。来源名称、文件路径、代码位置、Sheet/行号、指纹和证据说明仅用于内部分析，不得写入任何输出。

Excel 提取产生的 `work/excel` 内容属于中间结果，不得复制到正式输出目录。除非用户明确要求额外交付物，不得生成第三个文件。

### 3.8 验证

执行：

```bash
python "$SKILL_DIR/scripts/validate_output.py" \
  --workspace-root "$WORKSPACE_ROOT" \
  "$WORKSPACE_ROOT/docs/功能模块/待确认/<接口功能名称>-接口自动化资产.md" \
  "$WORKSPACE_ROOT/docs/功能模块/待确认/<接口功能名称>-资产转换报告.md"
```

多接口时将每个接口对应的两个文件全部传入。最低输入不完整时只传入转换报告。验证失败时修正输出，不得跳过。

## 4. 不可违背的规则

### 4.1 输出粒度

- 一个 `interface_key` 只生成一个功能级 Markdown；
- 不得按单条测试数据行拆文件；
- 辅助造数接口、查询接口、登录接口和 Mock 管理接口写为依赖动作，除非它们本身是被测目标。

### 4.2 执行状态

每个 SQL 动作、断言和 Mock 使用以下状态之一：

- `confirmed_executed`：当前可达代码、生命周期或已确认框架路径会执行；
- `configured_unverified`：存在配置，但无法确认框架消费；
- `referenced_not_reached`：存在引用，但当前路径不可达；
- `not_found`：扫描后未发现；
- `unknown`：证据不足。

不得把“文件中存在”直接写成“实际执行”。

### 4.3 数据准备仅支持 SQL

- 数据准备只认定 SQL 动作，包括用于造数、修改、清理或查询输入数据的 SQL；
- API、SSH、Shell、文件操作、配置修改和普通方法调用不得标为数据准备，应归入依赖动作或普通执行动作；
- SQL 可能来自测试方法、生命周期方法、公共方法、任意 Excel Sheet 或外部 SQL 文件；
- Sheet 名和列名只能作为候选信号，不能作为唯一判断依据；
- 不评估 SQL 安全性、数据积累风险或脱敏需求，只输出完整 SQL、阶段、适用场景、执行状态和输入输出；来源信息仅用于内部判断；
- 调用前 DELETE 属于前置清理，不得写成调用后恢复。

### 4.4 完整请求

- 所有业务请求字段、空值字段、嵌套对象和数组必须完整列出；
- 静态字段使用 Excel 或代码中的具体值；
- 运行时字段保留从代码还原的可执行表达式，例如 `${env.currentDate:yyyyMMdd}` 或 `${uuid:no-dash}`；
- 禁止使用无法从输入还原的通用占位符，例如 `${field_name}`、`${scenario.amount}`；
- 完整请求示例加场景差异必须能够重建每个场景，不要求重复整份相同报文；
- `i_seq_no` 只有在代码或映射证明确为 Excel 元数据时才从差异比较中忽略；如果实际发送，仍必须出现在完整请求中；
- 不得使用省略号、“同上”或“类似场景”代替字段、SQL、场景或断言。

### 4.5 最小执行阶段

动作阶段统一使用：

```text
before_suite
before_class
before_each
inline_before_call
call
inline_after_call
assertion
cleanup_on_success
cleanup_on_failure
cleanup_always
```

资产中保留阶段和顺序，不重复抄写完整代码生命周期说明。

### 4.6 不编造

- 实际调用和顺序以可达代码为主证据；
- 场景初值和预期值以配套测试数据为主证据；
- 字段契约只在接口文档或代码有证据时填写；
- 缺少字段含义、必输、长度、版本或超时时写“未获取”，不得根据名称或常识补造；
- 冲突不得静默覆盖，必须进入转换报告。
- 来源名称、文件路径、代码位置、Sheet/行号、指纹和证据说明不得出现在正式资产或转换报告中。

## 5. Excel 内容处理

从 `workbook.json` 读取原始值、显示值、单元格状态、公式、数字格式、隐藏信息和合并区域；从 TSV 快速浏览工作表。不得假设表头在第一行，也不得依赖固定 Sheet 名。

识别角色时综合工作表名称、表头、内容、代码读取路径和框架消费证据：

| 角色 | 常见信号 |
| --- | --- |
| 场景数据 | TestCaseId、案例 ID、多行输入和预期值 |
| 请求字段映射 | 请求字段、流程输入、`$Casedata{fieldName}`、字段路径 |
| SQL 数据准备/恢复 | SQL 文本、阶段、数据库、适用案例 |
| 断言配置 | JSONPath/XPath、断言方式、预期值 |
| Mock 配置 | 服务、方法、匹配条件、返回报文 |
| 通用配置 | 环境、数据库别名、开关、版本 |

ID、账号、日期和流水号优先使用提取结果中的显示值；同时保留原始值以便追溯。预期值必须绑定具体场景。

## 6. 增量刷新

输出必须保留：

```markdown
<!-- GENERATED:START -->
生成区域
<!-- GENERATED:END -->

<!-- MANUAL:START -->
人工区域
<!-- MANUAL:END -->
```

刷新时只读取和更新 `<WORKSPACE_ROOT>/docs/功能模块/待确认` 中的同名资产，只替换 `GENERATED` 区并保留 `MANUAL` 区。其他目录中的同名文件不得自动覆盖、移动或删除。可在内部使用输入文件的 SHA-256 判断变化，但不得将指纹写入输出。

## 7. 完成条件

只有同时满足以下条件才可交付：

- 最低输入已配对；
- 必要 Excel 已成功提取；
- 主接口和场景集合明确；
- 固定输出目录存在；
- 输入完整时，每个接口功能仅生成两个 Markdown，且均位于 `docs/功能模块/待确认`；
- 未经用户明确要求，没有生成其他交付文件；
- 全部测试数据已进入场景差异和预期信息，或在报告中明确排除；
- 完整请求可由完整示例和场景差异重建；
- 数据准备均为 SQL，且 SQL 内容完整；
- 断言、Mock、执行状态和适用场景完整；
- 无通用占位符、未替换模板变量或省略内容；
- 正式资产和转换报告均无来源、路径、位置、指纹或证据字段；
- 转换报告包含 Excel 提取、冲突、排除项和验证结果；
- `scripts/validate_output.py` 验证通过。
