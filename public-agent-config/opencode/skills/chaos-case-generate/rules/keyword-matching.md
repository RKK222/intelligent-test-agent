## L2 主问题判断

对以下主问题逐一判断（需求文本命中 `must_match` 才提问）：

| 主问题 | 必须出现特征 | 命中后必选关键词 |
|--------|-------------|-----------------|
| 是否涉及微服务架构？ | 微服务\|spring cloud\|dubbo\|service mesh\|gRPC | 微服务, 优雅启停, 服务熔断, 服务降级, 服务限流, 网络延迟 |

| 是否涉及数据库读写？ | 数据库\|读写\|主从\|分库分表\|sharding | 数据库故障, 连接池耗尽 |
| 是否涉及缓存策略？ | 缓存\|nos\|redis\|容器内存\|本地缓存\|分布式缓存 | 缓存故障, 网络延迟 |

| 是否涉及文件存储/上传？ | 文件\|存储\|nas\|fss\|oss\|nfs\|minio | 磁盘空间, 磁盘IO, 网络延迟 |

**方法**：分析需求文本，回答"是"则添加必选关键词到 `kws`。

## 互斥关键词处理

以下关键词同时出现时，保留优先级高的，移除互斥的：

| 关键词 | 互斥关键词 |
|--------|-----------|
| 网络延迟 | 网络丢包 (如果同场景已选网络延迟，网络丢包作为独立场景保留) |
| 数据库故障 | 连接池耗尽 (若数据库故障已涵盖连接池，则移除连接池耗尽) |

## 兜底策略

当 `kws` 为空时，推荐以下通用混沌案例：

| 场景 | 案例描述 | 匹配故障类型 |
|------|---------|-----------|
| A | CPU 满负载注入，验证系统的负载自动扩容或降级能力 | CPU高负载 |
| B | 网络延迟注入，验证系统的超时重试和熔断机制 | 网络延迟 |
| C | 磁盘空间耗尽，验证系统的磁盘告警与清理机制 | 磁盘空间 |
| D | 进程 Kill 注入，验证系统的高可用自愈能力 | 进程Kill |
| E | 内存溢出模拟，验证系统的内存限制与 OOM 处理 | 内存溢出 |
