# 异步任务测试规则

## Agent 使用方式

本文件对应附件 21 行功能规约；仅合并同一测试对象下名称相同、检查行为相同的重复行，形成 21 个可执行规则卡。不同名称或不同检查目的不继续合并。

`objectRuleBindings` 必须评估 ASYNC-01 至 ASYNC-21。命中项记录材料证据、最低覆盖、Phase A 中间物项和案例引用；不命中项可按相同理由批量登记 `ruleIds`，但不得漏号。

规则中的固定值、产品名、表名和例子只是候选检查点；只有当前材料明确确认时才能写入预期，否则写“需确认”。混沌、性能、安全和生产安全三板斧等非功能规约已移至暂缓文件，当前案例设计与 Review 不加载。

## 可执行规则

## 插入异步任务: 往异步任务作业表中插入异步任务作业。

### ASYNC-01 插入异步任务要求

- 触发条件：材料中出现“往异步任务作业表中插入作业时，要写入业务主键、作业类型等字段。”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：往异步任务作业表中插入作业时，要写入业务主键、作业类型等字段。参考详细涉及文档，分别确认作业类型和业务主键。
- 最低覆盖：1.输出至少1条案例。
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】插入异步任务: 往异步任务作业表中插入异步任务作业。 / 插入异步任务要求。
