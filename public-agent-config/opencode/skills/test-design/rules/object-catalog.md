# 测试对象识别目录

阶段 1 使用本目录识别对象，不在本阶段选择测试方法。

| 对象类型 | 典型信号 | 建议对象粒度 |
| --- | --- | --- |
| UI 页面/组件 | 页面、表单、弹窗、按钮、字段、联动、提示、权限可见性 | 一个可独立操作或提交的页面/组件流程 |
| 接口/服务契约 | API、服务、方法、路径、入参、出参、错误码、幂等 | 一个接口或一组不可分割的契约操作 |
| 业务流程/状态流 | 审批、提交、撤回、回退、状态迁移、跨系统链路 | 一个有明确开始、分支和终态的流程 |
| 批量任务 | 导入、导出、批次、批处理、重跑、断点续跑、汇总 | 一个批次生命周期或一个批处理作业 |
| 异步任务 | 消息、队列、调度、回调、重试、补偿、通知 | 一个异步触发到终态/补偿的链路 |
| 数据规则 | 计算、校验、映射、汇总、落库、唯一性、一致性 | 一组共享同一输入与结果的数据规则 |
| 配置/开关 | 参数、CMC、功能开关、阈值、环境差异 | 一个可独立改变行为的配置集合 |
| 权限/角色 | 角色、机构、菜单、数据权限、操作权限 | 一个权限决策点或角色差异集合 |
| 文件/报文 | 上传、下载、格式、字段、编码、文件大小、解析 | 一种文件/报文契约及其处理流程 |
| 技术改造 | 重构、迁移、替换、兼容、回退 | 一个可独立验证改造前后差异的变更单元 |
| 业务改造-其它 | 上下游投产、白盒检查、开关、影响范围、通用功能改造 | 一个不能归入 UI、接口、批量或异步任务的独立改造点 |

## 拆分规则

- 不把整份需求文档、整套系统或整个 S 子条目直接当成一个对象；
- 入口、输入、状态、依赖或预期结果明显不同的内容应拆开；
- 共享同一业务目标、状态和数据落点的页面与接口可分别识别，并通过 `objectRelations` 关联；
- 一个对象可以同时具有多个 `designSignals`，但阶段 1 不据此输出方法名；
- 每个对象必须有材料证据；没有证据的推测只放入 `gaps` 或 `questions`。
- 识别出异步任务、UI 界面、批量任务、接口或业务改造-其它后，必须通过 `spec-index.md` 加载相应对象规约，并逐条匹配触发条件、材料证据、最低覆盖和排除条件。
- 对象材料出现明确的大数据平台链路时，在主对象规约之外按 `spec-index.md` 加载 `big-data-common-cases.md`，并区分 `domainScopes`：BDP/入湖/Hudi/RA-RF 或具备数据湖算法上下文的 A-F1-F2 归 `BDP`；BDSP/平台化作业或作业组归 `BDSP`；湖表导出并传输给下游归 `OUTBOUND`；任一领域成立时同时加入 `COMMON`。`SEAS` 单独出现不能区分 BDP 与 BDSP；只有通用批量、CSV、文件、孤立短标识或数据加工信号时不得加载。
- 同一材料同时涉及 BDP 与 BDSP 时，优先按独立职责识别不同对象并用 `objectRelations` 连接；只有无法拆分的端到端职责才允许一个对象登记多个大数据 `domainScopes`，避免把两个平台的规则和案例混在一个对象中。
- 性能和生产安全三板斧不创建当前测试设计对象，也不触发方法选择或案例；对应规约处于暂缓状态。混沌与安全的旧规则卡同样暂缓，但不阻断 `chaos-case-generate`、`secure-case-recommend`：用户明确要求时强制选中；材料含有具体内容的专项章节，或对象事实显示具有独立覆盖价值的安全/容错风险时自动选中。空标题、占位文本和普通异常、权限或认证等孤立词不得自动升级为专项请求。

## objectId

`objectId` 仅用于阶段间结构化追溯和内部映射，不是用户可见名称。不得把 `OBJ-001`、`objectId` 或其变体写入正式文件名、文件标题、案例名称和最终回复。

按识别顺序使用稳定编号：

```text
OBJ-001
OBJ-002
...
```

同一轮分析中不得因排序变化重复或重用编号。
