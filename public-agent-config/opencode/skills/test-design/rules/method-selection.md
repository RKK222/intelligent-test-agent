# 阶段 2：测试方法选择规则

方法选择只发生在阶段 2。目标是用少量、互补的方法覆盖当前对象的主要风险，不是把方法清单逐项套到每个子条目。

用户没有指定方法时，由智能体依据阶段 1 的对象类型、`designSignals`、风险和证据自主选择：先确定一个最匹配主要风险的主方法，只有另一方法能补充主方法无法覆盖的独立高风险点时才增加辅助方法。方法数量不固定，但每个方法都必须有明确、不同的覆盖目标；没有新增覆盖价值的方法不选。

用户明确提出等价类法、正交法、路径法、场景法、生成接口测试案例、文本理解生成或增补法时，把这些方法记入 `requestedMethods` 并优先选中；历史称呼“接口法”“规则法”分别规范化到“生成接口测试案例”“文本理解生成”。若材料不足以形成该方法要求的 Phase A 中间物，不得静默忽略或改用其他方法，记录缺口并请求确认。

用户明确提出混沌案例、故障注入案例或混沌测试设计时，把 `chaos-case-generate` 记入 `requestedMethods`；明确提出安全案例、安全测试设计或安全案例推荐时，把 `secure-case-recommend` 记入 `requestedMethods`。二者是归属测试设计生成 Agent 的专项能力，不作为主方法或辅助方法计数，不因普通异常、权限或认证关键词自动选中。

## 方法映射

| 对象信号 | 方法 skill | Phase A 中间物 | Phase B 组装规则 |
| --- | --- | --- | --- |
| 接口/服务契约 | `test-design-api` | 接口覆盖矩阵 | 从矩阵组装接口七区块案例 |
| 输入域、长度、格式、枚举、范围、必输、边界 | `test-design-equivalence` | 等价类表 | 每个有效/无效类和关键边界组装案例 |
| 多条件、角色、配置、开关、互斥 | `test-design-orthogonal` | 因子水平表 | 先生成正交/判定组合，再组装案例 |
| 状态迁移、审批、页面流、分支、回退、重试 | `test-design-path` | Mermaid 路径图 | 先枚举路径，再按路径组装案例 |
| 端到端、批量、异步、下游异常、补偿、一致性 | `test-design-scenario` | Mermaid 场景图 | 先枚举场景，再按场景组装案例 |
| 简单单点规则、技术差异 | `test-design-direct` | 规则与验证点表 | 按规则点组装案例 |
| 页面动作与接口/状态/数据联动 | `test-design-augment` `mode=ui-api` | UI/API 联动映射 | 按联动项组装案例 |
| 已有案例按变更增补 | `test-design-augment` `mode=augment-flow` | 基线到增补点映射 | 把增补点组装进既有案例 |

## 选择步骤

1. 读取 `requestedMethods`；用户未指定时该列表为空；
2. 对每个对象列出阶段 1 的 `designSignals`、主要风险和证据；
3. 先选择一个主方法，再判断是否存在主方法无法覆盖的独立高风险点；
4. 仅为这些独立高风险点增加必要的辅助方法；用户指定的方法直接纳入；
5. 输出 `primaryMethod` 和 `selectedMethods`；每个选中方法记录 `methodSkill`、`role`（`PRIMARY` / `AUXILIARY`）、`selectionSource`（`AUTO` / `USER_REQUEST`）、唯一 `coverageTarget`、Phase A 模板、Phase B 转换规则和选择依据；用户指定多个方法时，仍按主要风险选其中一个作为主方法，其余标记为辅助方法；
6. 对看似相关但没有新增覆盖价值的方法写入内部 `notSelectedMethods`，不要生成其产物或案例；
7. 只加载选中的方法 skill；
8. 每个选中方法先执行 `phase=artifact`；
9. 所有 Phase A 中间物完成并冻结/确认后，才执行 `phase=case`。

## 组合规则

- `test-design-api` 可以与其他方法组合，但接口字段存在输入域、条件组合或状态流不等于必须同时选择全部相关方法；只有对应风险无法由接口覆盖矩阵充分表达时才增加辅助方法；
- UI/API 联动方法只覆盖联动关系；是否增加字段、组合或路径方法仍按独立高风险点判断；
- 不跨方法合并案例文件；同一方法内部可合并重复案例，并保留完整来源映射；
- 可以合并重复案例，不能删除 Phase A 中间物或失去覆盖关系。

## 停止条件

满足以下条件后停止增加方法：

- 主方法已覆盖对象的主要风险；
- 用户指定的方法均已纳入或已明确记录材料缺口；
- 剩余候选方法不能补充新的高风险覆盖目标，只会重复已有图、表、矩阵或案例。

## 禁止

- 不在阶段 1 选方法；
- 不在 Phase A 输出案例；
- 不在 Phase B 重新设计中间物；
- 不因材料不足把对象统一降级为文本理解生成；
- 不把对象类型直接等同于唯一方法；
- 不为每个子条目机械生成接口、等价类、正交、路径、场景、规则和增补的全套产物；
- 不选择覆盖目标相同、只会重复生成案例的方法；
- 不遗漏用户明确指定的方法；
- 无法形成必要中间物时记录缺口，并将阶段标为 `INCOMPLETE`。
