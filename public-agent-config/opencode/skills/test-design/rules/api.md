# 接口测试规则

## Agent 使用方式

本文件对应附件 27 行功能规约；仅合并同一测试对象下名称相同、检查行为相同的重复行，形成 27 个可执行规则卡。不同名称或不同检查目的不继续合并。

`objectRuleBindings` 必须评估 API-01 至 API-27。命中项记录材料证据、最低覆盖、Phase A 中间物项和案例引用；不命中项可按相同理由批量登记 `ruleIds`，但不得漏号。

规则中的固定值、产品名、表名和例子只是候选检查点；只有当前材料明确确认时才能写入预期，否则写“需确认”。混沌、性能、安全和生产安全三板斧等旧非功能规约已移至暂缓文件，当前案例设计与 Review 不加载这些旧规则卡；安全/混沌公共专项 Skill 仍按 `method-selection.md` 的证据决策单独选择。

## 可执行规则

## 健壮性测试: 接口的健壮性测试是确保系统在异常、高并发、网络抖动、重复请求等复杂场景下依然能够稳定、可靠运行的重要测试手段

### API-01 幂等

- 触发条件：材料中出现“验证当前待测功能是否有幂等场景，在重复调用时是否返回一致结果”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：1.设计重复调用的测试用例;2.设计幂等场景下的测试用例
- 最低覆盖：1.案例条数至少2条
- 排除条件：非幂等
- 来源定位：【属性】健壮性测试: 接口的健壮性测试是确保系统在异常、高并发、网络抖动、重复请求等复杂场景下依然能够稳定、可靠运行的重要测试手段 / 幂等。
- 证据来源：详细设计文档。

### API-02 非幂等

### API-03 并发调用验证

- 触发条件：材料中出现“评估接口并发调用峰值场景下接口能正常响应”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：模拟峰值并发用户同时调用接口。模拟突发流量（如秒杀、抢购）。；验证接口响应时间是否在可接受范围内。是否出现超时、500 错误、数据库连接池满等。是否有线程池、连接池配置合理。
- 最低覆盖：并发调用接口响应时间和异常场景、调用超时验证案例
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】健壮性测试: 接口的健壮性测试是确保系统在异常、高并发、网络抖动、重复请求等复杂场景下依然能够稳定、可靠运行的重要测试手段 / 并发调用验证。

### API-04 并发写入验证

- 触发条件：材料中出现“多个请求同时写入数据库数据正常”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：是否有事务控制。是否有并发写冲突（如乐观锁、悲观锁）。是否有数据库连接池限制。

- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。

## 功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试

### API-05 数据落表

- 触发条件：材料中出现“验证业务处理结果正确写入目标数据表”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：1.识别到详细设计文档中有insert或者update语句才执行该规则要求，在此基础上，执行前后对比目标表数据变化，验证字段映射关系和数据类型转换，表数据与请求报文数据一致
- 最低覆盖：识别到详细设计文档中有insert或者update语句才输出，如果仅有select则不输出，在此基础上1.需覆盖所有定义写入字段，2.包含正常值和边界值场景；3.字段默认值数据验证
- 排除条件：关联查询验证
- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 数据落表。
- 证据来源：详细设计文档。

### API-06 关联查询验证

- 触发条件：材料中出现“验证复杂SQL查询的关联逻辑正确性”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：识别到select语句中包含join或者union字段才执行关联查询规则要求，简单select不执行，在此基础上1.构造不同关联条件的测试数据，2.验证查询结果集完整性
- 最低覆盖：识别到select语句中包含join或者union字段才执行关联查询规则要求，简单select不执行，在此基础上1.需覆盖所有JOIN条件，2.包含空关联项场景
- 排除条件：数据落表
- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 关联查询验证。
- 证据来源：详细设计文档。

- 最低覆盖：1.需达到MCDC覆盖级别

- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 单条件分支覆盖。

### API-08 多条件组合分支判断

- 触发条件：材料中出现“验证多个条件组合后的分支跳转逻辑”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。

- 最低覆盖：1.需覆盖所有条件组合，2.需达到MCDC覆盖级别，3.需验证逻辑运算符（AND、OR、NOT）的处理

- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 多条件组合分支判断。

### API-10 分支覆盖验证

### API-11 存在接口调用

- 触发条件：材料中出现“接口实现逻辑中包含调用其他接口，并根据调用接口返回报文进行后续操作的处理流程”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：参考文档的接口逻辑中存在调用其他接口时执行此规则，调用接口前校验异常，验证上送给其他接口字段，其它接口返回成功、失败、未知，调接口后校验其他接口返回报文，如有多个其他接口，循环上述过程，组装返回报文
- 最低覆盖：覆盖其他接口调用前参数校验、调用返回后处理分支逻辑
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 存在接口调用。

### API-12 业务要素组合验证

- 最低覆盖：1.需覆盖所有有效等价类组合，2.需覆盖所有无效等价类组合，3.需验证异常值的处理逻辑
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。

### API-13 主参数必填验证

- 触发条件：材料中出现“验证接口对核心业务参数的强制性校验能力，确保必填字段在请求中存在且非空。”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：1. 构造请求体，故意缺失一个或多个标记为必填的主参数，2. 构造请求体，将必填参数设置为空字符串、null 或空对象
- 最低覆盖：1.案例需覆盖所有标记为必填的字段，2.错误提示必须明确标识缺失参数
- 排除条件：可选填参数默认值处理
- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 主参数必填验证。

### API-14 参数格式有效性验证

- 触发条件：材料中出现“验证接口对参数格式（如类型、长度、正则表达式等）的校验能力，确保输入数据符合业务规范。”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：1. 使用非法字符或不符合正则表达式的字符串构造参数值，2. 使用超出长度限制的字符串测试字段长度校验，3. 使用非数字类型值测试数值型字段，4. 使用非法日期格式测试日期字段
- 最低覆盖：1.需覆盖所有定义格式约束的字段,对每一个字段的校验各自单独生成至少一个案例，2.长度校验的边界值需包含定义长度的最大值和最大值+1
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 参数格式有效性验证。
- 证据来源：接口文档。

### API-15 可选填参数默认值处理

- 触发条件：材料中出现“验证接口在可选填参数缺失或为空时是否能正确应用默认值，确保业务逻辑的连续性。”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。

- 最低覆盖：1. 默认值应在接口文档中明确标注，对所有可选参数的默认值单独生成一条案例

- 来源定位：【属性】功能测试: 对接口的逻辑和输入进行约束，包含输入输出测试、逻辑分支测试 / 可选填参数默认值处理。
