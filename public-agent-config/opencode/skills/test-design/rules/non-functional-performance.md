### PERFORMANCE-01 非功能测试-性能

- 触发条件：材料中出现“非功能测试-性能”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：1.基准性能测试（Baseline Performance）；场景：单用户/低并发下执行核心功能（如登录、查询）；验证点：；响应时间（如API平均<500ms）；资源占用（CPU <30%，内存无泄漏）；2.负载测试（Load Testing）；场景：模拟典型用户并发（如1000用户同时下单）；验证点：；系统吞吐量（TPS/RPS）是否符合预期；错误率（<1%）；响应时间衰减（如不超过基线的200%）；3.压力测试（Stress Testing）；场景：逐步增加并发至系统极限（如从1000用户到5000用户）；验证点：；系统崩溃点或性能拐点；自动恢复能力（如降级、熔断机制）；4.稳定性测试（Endurance Testing）；场景：长时间（如24小时）持续中高负载运行；验证点：；内存泄漏（内存占用波动<10%）；响应时间稳定性（无逐渐劣化）；5.峰值测试（Spike Testing）；场景：瞬时突发流量（如秒杀活动开始时的10倍流量）；验证点：；系统是否崩溃或严重超时；弹性扩展能力（如自动扩容）；6.配置优化测试（Configuration Tuning）；场景：调整参数（如线程池大小、缓存策略）后复测性能；验证点：；性能提升效果（如TPS提升20%）；无副作用（如其他功能异常）；7.网络性能测试（Network Performance）；场景：模拟弱网（如高延迟、低带宽）或跨地域访问；验证点：；超时处理机制；数据一致性（如断网后恢复同步）
- 最低覆盖：按详细设计与实际业务生成案例。每条案例包含：测试标题、前置条件、测试步骤、测试数据、预期结果、测试类型、优先级、备注。；仅覆盖材料证实且与本次改造相关的场景。
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】非功能: / 非功能测试-性能。
- 证据来源：详细设计文档。
