# UI 页面测试规则

## Agent 使用方式

本文件对应附件 40 行功能规约；仅合并同一测试对象下名称相同、检查行为相同的重复行，形成 39 个可执行规则卡。不同名称或不同检查目的不继续合并。

`objectRuleBindings` 必须评估 UI-01 至 UI-39。命中项记录材料证据、最低覆盖、Phase A 中间物项和案例引用；不命中项可按相同理由批量登记 `ruleIds`，但不得漏号。

规则中的固定值、产品名、表名和例子只是候选检查点；只有当前材料明确确认时才能写入预期，否则写“需确认”。混沌、性能、安全和生产安全三板斧等旧非功能规约已移至暂缓文件，当前案例设计与 Review 不加载这些旧规则卡；安全/混沌公共专项 Skill 仍按 `method-selection.md` 的证据决策单独选择。

### UI-01 金额输入框合法性验证

- 触发条件：材料中出现“验证金额输入框金额长度测试，包含金额整数、小数部分，金额最大边界值验证，若系统可通过币种设置控制小数位数，需按照币种情况设计不同的类型，金融输入合法性验证”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：；1、验证金额输入框长度测试，按照业务需求、详细设计等文档设计金额整数部分应满足小于等于最大长度，小数部分应满足小于等于最大长度，金额最大边界值满足设计要求，若不满足，则需提示相关不允许信息；2、若系统可通过币种设置控制小数位数，小数部分长度需要根据币种进行相关 控制，如币种为人民币其本位币单位为“3-元”，小数为2位，10.12；日元：12.00；科威特第纳尔：1001.123；3、验证金额输入不允许非法字符，如：！·￥%等，若约定金额需大于0，则不允许输入0、0.0、0.00等值；4、若业务不允许输入负数，则需验证负数金额输入提示不允许输入等信息，特别关注-0的情况。
- 最低覆盖：至少输出2条案例
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】功能测试: / 金额输入框合法性验证。
- 证据来源：详细设计文档。

### UI-03 金额显示验证

- 触发条件：材料中出现“验证金额字段显示，包括金额右对齐显示，分隔符、小数点展现，打印，金额单位展示，部分特殊要求展示金额需悬浮汉字大写金额、金额后台存储”对应的能力、约束或改造。只凭规则标题、属性名称或附件示例不得判定命中。
- 必须分析：；1、验证金额字段是否右对齐，分隔符和小数点展示，其中小数点位数按照本位币单位不同展示不同，本位币为“3-元”，小数为2位，本位币单位“4-厘”/“5-毫”则为3位/4位小数，如人民币：10.12，日元：12.00，科威特第纳尔：1001.123；2、金额单位展示按照业务需求或应用系统约定在金额输入或者展示应有相应的单位，比如元、万元等；3、若为新终端、柜面通或者其他业务有明确要求的系统，需悬浮汉字大写金额；4、对于NOVA+境内主机应用，应以本位货币单位放大100倍整数形式在系统中存储、传输、计算、转换；在显示、打印时，再除以100，如人民币1元1分，输入为101，存储为101，显示/打印为1.01；如日元1日元，输入为100，存储为100，显示/打印为1.00。；5、对于NOVA+境外主机应用，金额字段的输入、展现、币种之间汇率计算时，应先访问NOVA+境外主机“地区货币表”（ATHPACUR）中的“货币最小使用单位”字段，判断货币的小数位数，再进行相关处理，对于“1-分”、“2-角”、""3-元""，该币种的金额类输入时，应放大100倍以整数形式存储，显示/打印时缩小100倍，“4-厘”/""5-毫""，表示币种有3位/4位小数，该币种的金额类输入时，应放大1000/10000倍以整数形式存储，显示/打印时缩小1000/10000倍。；6、针对涉及汇率兑换相关的金额，需验证数据库金额存的是汇率兑换后的金额还是带币种的金额，显示正确且记录正确
- 最低覆盖：至少输出2条案例
- 排除条件：材料未定义该能力，或本次改造与该能力无关时不适用；证据不足时记为 MISSING_EVIDENCE。
- 来源定位：【属性】功能测试: / 金额显示验证。
- 证据来源：详细设计文档。
