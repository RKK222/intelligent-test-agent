# 测试执行输出路径规则

应用工作区目录和 `I...-需求项/S...-子条目` 命名规则见测试设计公共 Skill 的 `test-design/rules/workspace-layout.md`。

测试执行产生的接口自动化脚本（包含请求报文）和可落盘执行证据必须与测试设计产物分区存放。

## 解析优先级

1. 用户明确指定执行产物文件路径时，写入该文件；
2. 用户明确指定执行产物目录路径时，写入该目录；
3. 用户没有明确指定路径时，沿用已评审案例的 `workspaceContext`，写入
   `<应用工作区根目录>/<需求项>/04-测试/<子条目>/042-测试执行/`。

已评审案例通常从同一需求项/子条目的 `041-测试设计/` 根目录读取；`041-测试设计/测试设计文档/` 只存放等价类、路径图等中间设计产物，不是默认案例来源。案例文件所在目录不是隐式执行输出目录。除非用户明确指定，不得把执行产物写入 `041-测试设计/`、案例同级 `测试执行/`、工作区根目录或其他替代目录。

## 执行产物命名

- 接口自动化脚本：`<案例名称>-接口自动化脚本.md`；
- 可落盘执行证据：`<案例名称>-执行结果.md`。

案例名称已经表达业务动作和验证点，执行阶段直接复用，不重新拼接内部编号、objectId、UUID 或阶段状态。

## 交接要求

- `test-execution-agent` 必须在 Task prompt 中传递解析后的 `outputTarget`、`workspaceContext`；无合法需求项/子条目上下文时返回 `INCOMPLETE`；
- `test-execution-api` 和 `generate-api-automation-markdown` 必须沿用该目标；
- 所有生成或更新文件都必须在结果的 `resolvedOutputTarget` 和 `generatedFiles` 中列明；
- 无法写入目标时明确返回 `INCOMPLETE`，不得静默改写到其他目录。
