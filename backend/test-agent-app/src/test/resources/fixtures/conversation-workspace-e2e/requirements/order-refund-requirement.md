# 订单退款需求说明

## 业务目标

为宠物诊所的在线订单提供可审计的退款能力，减少前台人工核对时间，并保证重复请求不会重复退款。

## 功能需求

1. 已支付且未全额退款的订单允许发起退款。
2. 单次退款金额必须大于 0，累计退款金额不得超过实付金额。
3. 同一 `idempotencyKey` 的重复请求返回第一次处理结果，不重复调用支付渠道。
4. 金额不超过 100 元时自动通过；超过 100 元进入人工复核。
5. 支付渠道超时后订单保持“退款处理中”，由补偿任务继续查询渠道结果。
6. 用户可以查询退款状态，但不能查看其他用户订单的退款记录。

## 非功能要求

- 接口 P95 响应时间不超过 500 ms（不含异步渠道处理）。
- 退款请求、审核和渠道回调必须携带同一 traceId。
- 日志不得记录银行卡号、支付 token 或完整身份证号。
- 状态变更和金额计算必须支持并发请求下的幂等与一致性。

## 验收标准

- 正常、边界、重复提交、并发、安全、超时补偿均有自动化案例。
- 退款状态变化在页面刷新后仍可恢复。
- 任一失败响应均返回可定位的错误码和 traceId。
