# 自动化代码库只读 Reference 验收

## 状态与权限

- “应用管理 → 工作空间管理”只列测试工作库；自动化配置统一位于工作台“引用配置 → 自动化代码库”，不再以工作空间/应用版本交互呈现。
- 左侧每张卡片对应一个已关联自动化版本库；管理员依次选择版本库、一个分支、仓库根或任意已有目录，并可编辑共享描述。文件不可选，不能新增远端目录。普通成员能进入同一页签只读查看当前配置和服务器状态。
- 每个 `(appId, repositoryId)` 最多只有一套当前配置。保存请求固定 `merge=false`，使用 `expectedGeneration` 乐观锁和幂等 `operationId`；跨应用、未关联版本库、错误类型和普通成员写请求均拒绝。
- 首次描述默认填充“版本库名称 / 分支 / 目录，只读自动化引用”；保存新分支、目录或描述时创建不可变 generation，在线服务器准备完成后才原子替换当前配置。离线服务器为 `DEFERRED`，恢复后补齐。
- 同分支“更新副本”创建新的目标提交 generation；“刷新 Git 指针”只读取实际分支、HEAD 和工作树状态，不 fetch、不切换。终止、重试和迟到响应必须受 generation fencing 保护。
- 存量迁移按应用和版本库归并同模板、多分支、多版本历史，选择最新有效配置作为一套当前 generation；旧模板、版本、副本和个人 worktree 保留审计，但退出创建、选择、同步和 Git 入口。

## 文件与安全

- 组合根出现“自动化代码库”，每个应用关联版本库最多展示一次；同名时追加版本库和分支。副本未就绪、提交不匹配、成员撤权只影响对应引用或后续请求。
- 验证目录、UTF-8/大文件分片、二进制下载和加入对话；路径穿越、符号链接、`.git`、伪造应用/版本库/generation 定位器和物理路径字段必须拒绝。
- 已打开标签必须携带服务端签发、绑定用户/主工作区/应用/版本库/generation 的只读租约；数据库只保存 SHA-256。切换 generation 后旧标签可继续读取，伪造、串用户、串工作区、过期租约均拒绝，刷新后使用新版。
- 验证编辑、上传、新建、删除、重命名、复制、移动、搜索、requirements 和全部 Git 入口均不可用于自动化引用。

## Generation 与 Run

- 保存后新展开目录和新 Run 使用新 generation；已打开标签及已启动 Run 继续绑定受租约保护的旧 generation，关闭或刷新后才使用新配置。
- 单个自动化副本不可用时，新 Run 只跳过该库并展示 `automationReferenceWarnings` 局部提示；主工作区、其它引用和 Run 继续可用。旧 generation 只有在 Run 租约和标签租约都释放后才退役，各服务器只清理自己的受管副本。
- `.opencode/opencode.jsonc` 是唯一运行时事实源。普通对话、命令、重发、批量和定时 Run 均不得由 Java 追加引用说明、逻辑路径或物理路径；保存、重新进入和新任务启动前通过既有文件 RPC 对账每个版本库唯一托管引用和精确只读权限。
- 主工作区、现有 `.opencode` 文档引用、应用代码库和历史会话保持原行为；历史自动化 worktree 不删除，但 recent、主选择器、个人 worktree 与 Git 操作入口忽略它们。
