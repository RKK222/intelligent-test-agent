# 自动化代码库只读 Reference 验收

## 状态与权限

- “应用管理 → 工作空间管理”只列测试工作库；自动化配置统一位于工作台“引用配置 → 自动化代码库”，不再以工作空间/应用版本交互呈现。
- 管理员可从已关联自动化代码库选择任意分支、任意已有目录、引用名称和 `yyyyMMdd` 首版本；文件不可选，不能新增远端目录。普通成员能进入同一页签只读查看目录和当前版本，但不调用管理员版本库 API。
- 停用配置从普通组合树和普通成员目录中隐藏，但管理员配置页仍显示并可重新启用；新增后续版本复用配置目录，必须由管理员显式激活。
- 新建自动化配置的首个版本自动成为当前版本；后续新增版本不自动切换。
- `APP_ADMIN` 与 `SUPER_ADMIN` 可幂等激活归属当前应用和配置的 `ACTIVE` 版本，普通成员只能查看；跨应用、跨配置和非自动化版本均拒绝。
- 存量迁移按配置选择创建时间最新的 `ACTIVE` 版本，无可用版本时保持空并显示局部告警。

## 文件与安全

- 组合根出现“自动化代码库”，多配置均展示；同名时追加版本库和分支。副本未就绪、提交不匹配、成员撤权只影响对应引用或后续请求。
- 验证目录、UTF-8/大文件分片、二进制下载和加入对话；路径穿越、符号链接、`.git`、伪造配置/版本 ID 和物理路径字段必须拒绝。
- 验证编辑、上传、新建、删除、重命名、复制、移动、搜索、requirements 和全部 Git 入口均不可用于自动化引用。

## 版本与 Run

- 切换后新展开目录和新 Run 使用新版；已打开标签及已启动 Run 继续绑定旧版本 ID，关闭或刷新后才使用新版。
- 普通对话、命令、重发、批量和定时 Run 的 OpenCode 出站 system 上下文包含名称、版本、只读说明和内部路径；用户消息、API 响应、错误、日志与持久化消息不出现物理路径。
- 主工作区、现有 `.opencode` 文档引用、应用代码库和历史会话保持原行为；历史自动化 worktree 不删除，但 recent、主选择器、个人 worktree 与 Git 操作入口忽略它们。
