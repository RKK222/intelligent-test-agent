# 顶部上下文选择器现代化设计

## 1. 背景与目标

MIMO 测试智能体工作台顶部依次提供“应用、工作空间、版本”三个选择器。现状使用三个外观接近表单输入框的独立白色按钮，功能清晰，但没有表达三者共同构成当前工作上下文，边界、圆角与展开反馈也偏传统。

本次改造的目标是把三个选择器重塑为一条现代、紧凑且具有 MIMO 品牌识别度的“上下文轨道”，同时统一下拉菜单的视觉层级。改造不改变任何菜单内容、数据来源、默认选择、事件回调或运行逻辑。

目标用户是使用 Web IDE 完成测试设计、执行和分析的研发与测试人员。这个区域的唯一任务是让用户快速识别并切换当前应用、工作空间和版本。

## 2. 已确认方向

用户从三个候选方向中确认采用方案 A“精密上下文舱”，并明确要求把下拉菜单纳入同一轮优化：

- 方案 A：三个选择器共享一个连续容器，通过内部发丝分隔线表达共同上下文。
- 方案 B：三个独立浮动芯片，识别直接但占用更大，且容易落入通用后台模板风格。
- 方案 C：用路径箭头表达从属关系，最轻盈，但点击边界和控件属性不如方案 A 明确。

最终方案去掉通用的独立卡片和装饰性图标底座，只保留与本产品真实信息结构有关的连续轨道。左侧工行红信号条是唯一高辨识度装饰，避免多个视觉重点相互竞争。

## 3. 视觉系统

### 3.1 色彩

所有颜色继续服从现有 shell token，不为该组件建立另一套主题：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 冷雾画布 | `#F0F4FA` | 顶栏背景，与三栏间距画布一致 |
| 纯白表面 | `#FFFFFF` | 上下文轨道与下拉菜单表面 |
| 墨黑正文 | `#151922` | 当前值和菜单主要信息 |
| 工行红 | `#C8161D` | 信号条、焦点、展开和选中状态 |
| 深品牌红 | `#8F1D2C` | 红色文字与高对比状态 |
| 发丝边框 | `#DFE4EC` | 外框、内部分隔与菜单边界 |

实际实现优先复用 `--ta-shell-*` 变量；只有现有 token 无法准确表达的中性色才使用局部回退值。

### 3.2 字体

- 当前值与菜单正文：现有 `--font-sans`，优先 Inter / Geist Sans / PingFang SC，使用 11–12px、600 字重。
- 中文字段标签：PingFang SC / Microsoft YaHei，使用 9–10px、500 字重和轻微字距，作为工具性辅助信息。
- 版本号等短数据：沿用 Geist / 现有无衬线字体，不额外加载网络字体；不为少量数字引入新依赖。

### 3.3 几何与层级

- 整体高度：34px，在现有 36px 顶栏和 44px 视觉带中保持垂直居中。
- 外层圆角：11px；分段交互面圆角：7px。
- 外框：1px 发丝边框；阴影只提供轻微浮层分离，不形成卡片堆叠感。
- 分隔线：相邻分段之间使用短竖线，顶部和底部保留呼吸空间。
- 信号条：轨道左侧使用 3px × 15px 工行红圆角竖条，表达当前工作上下文入口。

## 4. 布局设计

三个选择器继续按“应用、工作空间、版本”顺序排列，并保留各自宽度约束和文本截断。外层增加统一上下文容器，内部按钮移除彼此重复的独立边框。

```text
┌──────────────────────────────────────────────────────────────┐
│ ▌ 应用  F-COSS ⌄ │ 工作空间  ⚗ workspace ⌄ │ 版本  20260618 ⌄ │
└──────────────────────────────────────────────────────────────┘
  ↑ 品牌信号条          ↑ 内部分隔线                ↑ 内部分隔线
```

组件结构保持在 `FigmaShell.vue` 内，不抽取新组件，以免为单一顶栏样式增加不必要的接口和文件。现有三个菜单 wrapper 继续承载定位和事件，新增一个仅负责视觉分组的容器类。

## 5. 交互状态

### 5.1 默认与悬停

- 默认状态只显示统一外框，不显示三个独立输入框边框。
- 鼠标悬停某一分段时，只给该分段增加冷灰底色；其它分段保持稳定。
- 箭头、图标和文本基线统一，避免展开前后发生位移。

### 5.2 键盘焦点

- 保留原生 button 和现有可访问名称。
- `:focus-visible` 使用清晰的工行红焦点环和柔红底，不依赖颜色变化之外的单一提示。
- 分段圆角与外层圆角协调，首尾分段焦点态不溢出上下文容器。

### 5.3 展开与按下

- 当前展开分段使用柔红背景、深品牌红文字和箭头。
- 轨道外框在任一菜单展开时提升为工行红弱描边，保持整体上下文感。
- 箭头继续复用现有旋转逻辑，动效控制在 120–160ms。
- `prefers-reduced-motion: reduce` 下移除非必要过渡，不影响状态识别。

### 5.4 禁用

- 应用源码模式中的“源码快照”仍保持不可点击。
- 禁用分段降低文字和图标对比度，但不降低到难以辨识；鼠标使用默认光标，不展示可操作悬停态。

## 6. 下拉菜单

三个下拉菜单继续使用现有内容和定位逻辑，只统一外观：

- 圆角调整为 12px，边框使用 shell 发丝边框。
- 阴影改为两层低透明阴影，清晰区分顶栏与菜单，不产生厚重悬浮感。
- 菜单内边距和项目间距保持紧凑，项目圆角为 8px。
- 选中项使用柔红底、工行红图标和现有对勾；悬停只使用冷灰底。
- 分组标题、管理入口、空态、错误态和禁用态继续保留现有语义与操作。
- 工作空间菜单仍从工作空间分段左侧对齐；版本菜单仍在视口内向右对齐，不改变定位算法。

## 7. 响应式与兼容性

- 继续沿用现有 `clamp()` 宽度和 900px 断点，不增加新的 JavaScript 布局逻辑。
- 窄屏缩短三个分段宽度和水平内边距，标签与当前值仍允许省略号截断。
- 不改变 Logo、右侧手册、运行态摘要和头像位置。
- 使用企业 Chromium 108 支持的常规 flex、border、box-shadow 和伪元素，不依赖 `:has()`、容器查询或新版 CSS `scale`。
- 所有菜单继续通过原有 Vue 条件渲染和事件处理工作。

## 9. 非目标与影响评估

本次不改变：

- 应用、工作空间、版本的加载与切换逻辑。
- 应用源码和测试工作空间的分组与管理入口。
- 顶栏高度、整体三栏布局、Logo、手册、运行态摘要和用户菜单。
- HTTP API、RunEvent SSE、DTO、数据库、Flyway migration、权限、安全、日志或性能契约。

兼容性风险主要来自窄屏横向空间和测试中既有样式断言。实现时通过保留现有宽度约束、900px 断点和事件节点来降低风险；视觉验收需要覆盖常规桌面宽度和窄屏断点。

## 10. 验收标准

1. 顶部三个选择器视觉上形成一条连续、现代的上下文轨道，不再像三个并列输入框。
2. 应用、工作空间、版本的内容、顺序、下拉项和切换结果与改造前一致。
3. 默认、悬停、键盘焦点、展开、选中和禁用状态清晰且统一。
4. 三个下拉菜单的圆角、阴影、选中项和间距使用同一视觉系统。
5. 常规桌面与 900px 窄屏断点下不遮挡 Logo 或右侧工具组，长名称继续正确截断。
6. 定向测试、类型检查和生产构建通过，稳定文档同步完成。
