# 对话会话终态展示隔离设计

## 背景

`FigmaChatPanel` 会在一次 Run 结束时把失败、停止或完成结果记录到组件本地状态。右侧聊天面板在切换 Session 时会复用同一个 Vue 组件实例，因此会话 A 的本地失败标记可能继续作用于会话 B，导致正常会话错误显示“您的请求断开，请重试”和“任务失败”。

## 目标

- 失败、停止和完成提示只作用于产生该终态的当前会话。
- 从失败会话切换到其他正常会话后，不展示旧会话的失败卡片或失败页脚。
- 再次进入原失败会话时，继续根据该会话恢复出的持久化 Run 状态和消息展示失败提示。
- 空白草稿首次创建真实 Session 时仍视为同一轮对话，不因 Session ID 从空变为非空而清除当前 Run 的终态状态。

## 方案选择

采用在已建立的根 Session 身份发生变化时重置 `FigmaChatPanel` 本地终态标记的方案。该方案沿用组件现有的 `currentSessionId` 切换观察点，只清理 `wasFailed`、`wasStopped` 和 `wasCompleted`，不重新挂载组件，也不影响输入、会话列表抽屉、滚动位置或其他交互状态。

不采用给组件设置 Session `key` 的方案，因为强制重新挂载会同时丢失与本缺陷无关的局部 UI 状态。不采用彻底删除本地终态标记、仅从消息和 Run 状态推导的方案，因为这会扩大终态时序处理的修改范围。

## 状态流转

1. 同一 Session 的 Run 从运行中进入终态时，继续按现有逻辑记录本地终态标记。
2. `currentSessionId` 从一个非空 Session ID 变为不同值（包括新 Session 或空白新对话）时，清除三个本地终态标记。
3. `currentSessionId` 从空值变为首次创建的真实 Session ID 时不清除标记，因为这是同一草稿 Run 的身份落成。
4. 历史会话正文和 Run 状态恢复后，失败提示继续由当前会话的 `runtimeStatus` 或当前会话错误消息推导，不依赖上一会话的本地状态。

## 测试

在 `FigmaChatPanel.test.ts` 添加组件回归测试：

1. 挂载会话 A，模拟 Run 从运行中结束为失败，确认显示失败卡片和失败页脚。
2. 在不重新挂载组件的情况下切换到有正常消息的会话 B，确认失败卡片和失败页脚消失。
3. 切回会话 A，并传入其持久化 `FAILED` 状态，确认失败提示恢复。

运行组件定向测试、agent-web 测试，以及前端类型检查。若完整检查受既有环境问题阻塞，保留命令和失败证据。

## 影响范围

修改范围仅包含 agent-web 聊天面板、对应测试和稳定前端说明文档。不新增或修改 HTTP API、RunEvent 事件、DTO、数据库、权限、安全边界或后端逻辑；不修改 OpenCode 源码快照。
