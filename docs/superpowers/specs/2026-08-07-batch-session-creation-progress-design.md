# 批量子条目会话创建进度页设计

## 背景

批量子条目弹层当前只在编排执行期间依赖父组件的 `running` 状态禁用操作。编排结束后，弹层继续保留原选择并恢复执行按钮；用户再次点击时，前端会生成新的 `batchId` 和 `itemRequestId`，后端会将其视为新批次，因此原有基于条目请求 ID 的幂等约束无法阻止同一弹层内重复发起。

## 目标

- 点击“立刻执行”或“定时执行”后，同步锁定提交入口并切换到会话创建进度页。
- 进度页逐项展示所选子条目的资料准备、会话创建、Run 启动或定时任务创建结果。
- 创建失败项可以单笔重试，也可以一次重试全部失败项；重试继续使用本批次原有幂等身份。
- 进度页不自动关闭。用户主动关闭后，本次批次结束；再次打开批量弹层时必须是全新批次。
- 关闭前若仍有子条目没有成功创建会话，必须二次确认。

## 交互设计

### 选择状态

弹层沿用现有候选搜索、多选、50 项上限、生成要求和立即/定时配置。点击执行按钮时，组件必须先在本地同步切换为“创建进度”状态，再向上层发出执行请求，避免 Vue 属性回写前的重复点击窗口。

切换后不再展示可编辑的选择和定时配置区域，也不能通过遮罩、关闭按钮或键盘操作退出正在创建的批次。

### 创建进度状态

进度页保留需求项、子条目、文件数和逐项状态，状态包括：

- 准备资料；
- 创建会话；
- 启动立即执行；
- 创建定时任务；
- 创建成功；
- 创建失败。

立即模式中，Session 创建成功但 Run 启动失败时必须保留 `sessionId`，页面应显示“会话已创建，执行启动失败”。该项仍可重试，但重试必须继续使用原 `itemRequestId` 和 Run `clientRequestId`，不得产生第二个 Session。

定时模式继续调用现有任务创建接口；该接口在同一事务中创建 Session 和任务。普通失败重试沿用原 `batchId`、`itemRequestId`、任务请求 ID 和原时间分配。容量冲突仍按既有规则刷新时段数据；进度页为容量冲突失败项展示现有时间选择器，只允许重新分配这些失败项的时间，容量不足时禁用重试。

进度页提供：

- 每个失败项的“重试”按钮；
- “重试全部失败项”按钮；
- 定时容量冲突失败项的时间重新选择区域；
- 用户主动关闭入口。

创建或重试正在进行时，所有重试和关闭入口禁用。

### 关闭与重置

当所有所选条目均已取得 `sessionId` 时，用户关闭进度页无需确认。只要存在未取得 `sessionId` 的条目，关闭时使用现有页面确认组件提示仍有会话未创建成功；用户取消则留在进度页，确认后关闭。

关闭只结束前端本次批次管理，不取消已创建的 Session、Run 或定时任务。关闭完成后必须清空：

- 所选子条目；
- 生成要求和定时选择；
- 逐项执行状态；
- 当前请求；
- `batchId`、`itemRequestId`、Run/任务请求 ID 和时间分配。

再次打开弹层时恢复默认要求“请生成子条目测试案例。”，由下一次提交生成全新批次身份。

## 状态与组件边界

`BatchTestCaseGenerationDialog.vue` 负责选择状态和创建进度状态的切换、同步提交门禁、单项/批量重试按钮及关闭确认。

`useBatchTestCaseGeneration.ts` 继续负责四路并发和幂等身份，新增：

- 按指定条目重试的稳定入口；
- 保留 Session 已创建但后续步骤失败时的 `sessionId`；
- 显式 `reset()`，只在用户确认关闭后清理本批次身份和状态。

`FigmaChatPanel.vue` 负责弹层开关和关闭确认展示；`AgentWorkbench.vue` 继续负责调用编排、刷新会话与待执行任务以及全局反馈，不切换当前对话。

## 错误处理

- 资料读取失败、无可读文件或上下文超限：条目没有 `sessionId`，标记创建失败。
- Session 创建失败：保留安全错误码和提示，允许使用原幂等身份重试。
- 立即 Run 启动失败：保留已创建的 `sessionId`，重试不得创建新 Session。
- 定时容量冲突：沿用现有容量冲突标识和时段刷新；失败项重新选择具备足够余量的时间后，使用原幂等身份重试。
- 顶层前置校验失败且尚未进入条目编排：恢复选择状态并显示安全反馈；只有实际受理的批次进入创建进度页。

## 测试设计

- 组件测试验证点击后立即进入不可编辑的进度状态，连续点击只发出一次执行事件。
- 组件测试验证单项重试和全部失败项重试仅携带失败条目。
- 组件测试验证运行期间不可关闭；全部 Session 已创建时直接关闭；存在未创建 Session 的失败项时需要确认。
- 组件测试验证关闭并重新打开后选择、要求、时间、状态和批次身份全部重置。
- 编排测试验证 Run 启动失败保留 `sessionId`，重试复用原 Session、条目请求 ID 和 Run 请求 ID。
- 回归现有立即执行、定时分配、容量冲突、四路并发、部分失败继续、50 项上限和 `#` 候选同源行为。
- 执行前端全量 Vitest、typecheck、production build 和目标 Playwright。

## 兼容性与范围

本次不修改 HTTP API、RunEvent、数据库、Flyway、后端 Session 幂等约束、OpenCode 源码、generated SDK 或环境配置。已有普通单条发送、单条定时和批量后端请求保持兼容；变化仅限批量弹层的前端生命周期与展示语义。
