# 批量定时选择交互优化设计

## 背景

批量生成弹层当前高度为 `70vh`。打开定时选择区域后，页面仍同时展示“立刻执行”和定时区域内的“定时执行”，并且定时选择区域没有独立关闭入口，用户容易混淆当前执行方式，也无法便捷返回立即执行模式。

## 目标

- 批量弹层保持 `70vw`，高度从 `70vh` 调整为平台视口高度的 90%，即 `90vh`。
- 定时选择区域提供独立的小叉关闭图标。
- 立即执行与定时执行共用底部主操作位置，并根据当前模式互斥显示。
- 不改变批量创建进度页、重试、幂等身份、定时容量分配或后端协议。

## 交互设计

### 默认选择状态

定时选择区域关闭时，底部继续展示：

- “选择定时”次操作按钮；
- “立刻执行”主操作按钮。

### 定时选择状态

点击“选择定时”后：

- 展开现有 `ExecutionTimePicker`；
- 在定时选择标题右侧展示小叉图标，按钮可访问名称为“关闭定时选择”；
- 隐藏“选择定时”和“立刻执行”，避免同时出现两种执行方式；
- 尚未选择有效时间时，原主操作位置不展示执行按钮；
- 选择至少一个时间且现有容量分配校验通过后，原“立刻执行”位置展示“定时执行”；
- 容量不足时继续显示现有容量提示，并隐藏“定时执行”，避免出现看似可提交的主操作。

点击小叉后只收起定时选择区域，保留已选子条目和批量案例生成要求，并恢复“选择定时”和“立刻执行”。为避免下一次打开时误用旧选择，关闭定时选择时同时清空已选夜间时间、自定义时间及自定义时间校验提示。

### 创建进度状态

创建进度页及容量冲突失败项的重新选时区域保持现状。新增的小叉只属于首次提交前的定时选择区域，不用于关闭进度页中的容量冲突重选区域。

## 状态与实现边界

改动集中在 `BatchTestCaseGenerationDialog.vue`：

- 新增 `closeSchedule()` 清理定时选择局部状态并收起区域；
- 以 `scheduleOpen` 和 `selectedScheduleTimes`/`scheduleAllocation` 决定底部按钮；
- 将首次定时提交按钮从定时面板内部移动到底部主操作位置；
- 弹层内联高度改为 `90vh`。

不修改 `ExecutionTimePicker.vue`、`FigmaChatPanel.vue`、`AgentWorkbench.vue`、编排 composable 或后端接口。

## 测试设计

- 组件测试验证弹层为 `70vw × 90vh`。
- 组件测试验证打开定时选择后，小叉可见，“选择定时”和“立刻执行”消失。
- 组件测试验证未选时间时“定时执行”不存在，选择有效时间后在底部主操作位出现并可提交。
- 组件测试验证点击小叉后定时区域关闭、立即执行入口恢复，并且重新打开时旧时间选择已清空。
- 回归现有多夜间时段、管理员自定义时间、容量不足、进度页容量冲突重选和目标 Playwright 批量流程。

## 兼容性与范围

本次只改变批量弹层首次提交前的前端布局和交互，不修改 HTTP API、RunEvent、数据库/Flyway、后端、权限、安全、性能路径、环境配置、generated SDK 或 OpenCode 源码。
